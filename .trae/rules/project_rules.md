# 项目规则

## Git 工作流（用户明确要求 2026-09-16）
- 直接提交并推送到 `main`，**不要建功能分支、不要开 PR**。
- 推送前跑 `node tools/check-all.js` 自验（须**全绿**：所有实跑项 ✓、0 失败）。
  ★ **不要写死步数**——这里原先写「10/10」，而自检链从 v2.0.6 起已扩到 14 步（当前实跑 12、
  ⊘2）。数字一旦写死就会随版本腐坏，而它是给 Agent 看的规则，腐坏后 Agent 会按错误口径判断。
  口径记住两条：
  · `⊘`（可选加强项，如 ESLint / tsc 缺 node_modules）= **未执行**，不算失败；
  · 一旦出现第一个 `✗`，它**之后**的所有结论都不成立，从第一个 ✗ 开始修。
