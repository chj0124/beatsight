# BeatSight 时值节拍器

> 吉他练习用的节奏可视化节拍器 —— 把抽象的「时值」翻译成「长度」，一眼看懂节奏型。

单文件、零依赖、双击即用的网页应用（v1.4 起在线版支持 PWA 离线安装——`manifest.webmanifest`/`sw.js`/图标文件这组独立文件只服务在线部署，不影响本地单文件直开）。设计目标：保留传统节拍器的可靠性，同时解决"听不出附点/切分"的自学痛点。

- **本地使用**：双击 `index.html`（任意现代浏览器，手机浏览器同样适用）
- ⚠️ **两种用法的数据不互通**：`file://` 与 `https://` 是不同 origin，`localStorage` 不共享。在本地攒的预设，打开在线版会看到空的——迁移请用「导出预设」/「导入预设」

## 开发者：改完跑一条命令

```bash
node tools/check-all.js          # 共 12 步：语法 → 架构约束 → 零依赖 lint → 版本一致性 → 文档一致性 → ESLint（可选）→ 类型检查（可选）→ DOM 引用 → 浏览器冒烟（环境可选）→ 全量测试 → 死循环看门狗 → 行覆盖率
node tools/check-all.js --quick  # 跳过 243 组全量组合扫描（改代码时用）
```

**这里刻意不写"约几秒"**（v2.0.5 起由 `tools/check-docs.js` 强制）：耗时随机器、Node 版本、跑不跑 `FULL_SCAN` 而变，写死在文档里必然过期——历史上这两个数字已经被"改正"过一次又歪了。命令末尾自己会打印「全部通过 · 实跑 N/M 项 · 用时 Xs」。

**核心闸门零依赖、零安装，Node ≥ 22 直接跑**——不装任何东西也能跑完整套检查。其中有 **2 步是可选加强项**（ESLint / 类型检查）：`npm install` 装了才跑，没装就在汇总里标 **⊘ 未安装依赖，未执行**、并打印「实跑 N/M 项」——**不会显示成 ✓**（区分"没查"和"查了通过"，否则汇总就在撒谎）。想启用，仓库根跑一次 `npm install` 即可；**它们绝不会因为"没装开发依赖"堵住部署**。

另有 **1 步是"环境可选"**（第 9 步浏览器冒烟）：本机装了 Chrome / Edge 才会跑，没有就同样标 ⊘。它与上面两步的区别是——**构建镜像里必然没有浏览器**，所以 `--strict-env` 也不把它算作失败（浏览器是"环境能力"而非"开发依赖"，没有 `npm ci` 能把它装进产物）。它验的是桩测不出的那一整类：真实布局与样式、真实帧率、真实 Service Worker、控制台零报错。

类型检查这步把关的是**模块接口与数据模型**：接口方法名拼错、`S.xxx` 状态字段拼错、类型不符的赋值都能拦住（带 "Did you mean" 提示）；它不管 DOM 元素类型（那由 `check-dom-ids.js` 管）。它的严格开关**该开的都开了**——strict 家族 9 项（含 `noImplicitAny` / `strictNullChecks`）加 `noImplicitReturns` / `noFallthroughCasesInSwitch` 全部打开，取舍与开启路径写在 `tools/tsconfig.typecheck.json`。

项目**不用 GitHub Actions**，机器检查全由上面这条命令承担——但它在两条发布渠道上的位置不一样，**别把"Cloudflare 会拦"当成可以跳过本地自验的理由**：

- **WorkBuddy**：纯手动发布，没有任何机制拦你，只能发布前自己跑一遍。
- **Cloudflare**：`wrangler.jsonc` 里的 `build.command` 串了全量自验（`&&` 短路，不通过即中止），但**Workers Builds（Git 集成构建）不读 wrangler 配置里的自定义构建命令**（Cloudflare 官方既有行为）——所以线上那次构建跑什么，取决于 Dashboard 里那串命令，而它不在版本库里。**能称作"硬闸门"的只有本地/命令行 `wrangler deploy` 这条路**。（v2.0.5 修正：此前这里写的是"构建命令里串了全量检查，不通过就不部署（硬闸门）"，把仓库里的一份配置当成了线上事实。）

```bash
sh tools/install-hooks.sh   # 可选但推荐：装一次 pre-commit 钩子，每次提交自动跑 --quick 快速自验
```

**发布前清单**：① `node tools/check-all.js`（全量，不是 --quick）通过——Cloudflare 构建时会再跑一遍，本地过不了线上也过不了；② 把 `index.html` 的 `const VERSION` bump 到本次版本号（**每次发版都要 bump，工程版也不例外**；唯一真相源，`<title>` / 品牌区 / chip 三处显示自动跟着变；`package.json` / `package-lock.json` 的 version 由 `check-version.js` 一并把关）；③ 浏览与资源自验：`node tools/smoke.js` 已自动覆盖「能启动、无控制台报错、版本号一致、可视化网格渲染、关键元素样式、Service Worker 注册、播放态帧率」——**但它看不出"好不好用"**，视觉/手感类改动仍要人眼过一遍；④ 涉及后台播放的改动另需真人验收（见 docs/DEVELOPMENT.md §5）。

**两条渠道怎么发**：① Cloudflare 不需要额外动作——推 `main` 就自动构建部署，这是常规发版；② WorkBuddy 要单独手动发（用 WorkBuddy 打开项目去发布），且因为它只在你用它的时候才更新，**落后几个版本是常态**。两个地址的数据也不互通（各自 `localStorage`，要迁移用「导出预设」）。

### 核心交互细节

- **时值可视化**：音符块宽度与时值严格成正比。**曲式模式下网格是歌曲小节上的 4 行滚动窗口**（播到第 k 小节，四行就是第 k…k+3 小节，可跨段取到下一段的型，跟着播放往前滚）；预设模式下四行就是当前这个型的全部小节（1 小节的型就画 1 行）
- **弹跳球**：球在相邻发声点之间跳重力抛物线，落点即下一颗音的真实发声时刻——看着球下落提前出手，如同跟指挥棒；跳距与时值成正比，静音小节照跳（视觉兜底），休止符长跳跨过
- **十六分小格**：每个音符块内按十六分等分刻度，跑完一格四边亮一下（绿块上闪白光、白/暗块上闪绿光）
- **当前高亮**：正在弹的音符块白色进度填充 + 绿色描边提示，弹完定格纯白——四种时值观感一致，绿色只做功能强调
- **静音拍训练**：每 4 小节静音第 4 小节，强制内心数拍
- **扫弦方向**（v1.9）：节奏型可标注每个音是 ↓ 下扫还是 ↑ 上扫，格子内显示方向徽标；内置「民谣扫弦」已按其名字标好 ↓↓↑↑↓↑，编辑器里可逐个改。方向只影响记谱显示，**不改变任何发声**
- **两个节拍入口**（v2.4）：预设库顶部有「普通节拍 / 带扫弦」切换条。**普通节拍**只出节拍音与强弱重音、不显示扫弦记谱；**带扫弦的节拍**在节拍上叠加扫弦节奏（下扫/上扫 + 弦区音色）。速度、拍号、音量、Swing、音色两条轨**完全共享**——切过去接着按原速度练，不必重调；切到普通轨时带扫弦的节奏型会从列表里隐去（并提示「已隐藏 N 个」），当前选中的那个会自动回退到普通节奏型
- **扫弦谱下节拍器照响**（v2.5）：带扫弦的节拍轨上，**每一拍都出节拍音**，扫弦声叠在扫弦记谱的位置上（同时刻，不推后）。空扫（只动手不出声）与纯休止所在的拍**也有节拍音**——扫弦谱记的是右手，不该顺带把拍子吞掉
- **两条独立音量条**（v2.5）：音量区分「**节拍**」（每拍拍点 / 预备拍 / 歌词提示音）与「**扫弦**」（弦区扫弦声）两条并列滑条，各调各的 —— 把「节拍」拉到 0 扫弦照响，反之亦然。「扫弦」条只在带扫弦的节拍轨出现；「重拍增强」对两条声部都生效
- **整首连播**（v2.5）：预设库「示例曲」分组顶部一键**按原曲顺序串起全部 10 段并循环**，不必先进「编排曲式」面板；下面的**段序条**（`1 开头` … `10 主歌二`）高亮当前段、点某一段=只循环那一段。想单练某一型就直接点它——会立刻退回单型循环（两个入口对等）
- **示例曲是逐小节谱**（v2.6）：《在他乡》全曲 **30 小节**、5 个型各 **1 小节**，段长 `1/3/4/2/4/2/4/2/6/2`（不再是"每段垫到 4 的倍数"的 44 小节）。于是滚动网格滚过段边界时，**同一屏里会出现不同的型**（例如第 9 小节起那一屏是「副歌的 P2 + 收束的 P1 + 主歌的 P3 ×2」）——这才是这首歌本来的样子。段内歌词与小节**一一对应**，多出来的空白小节不再存在
- **练习量**（v1.9）：练习量区选「8 / 16 / 32 小节」或「5 / 10 分钟」，到点自动停止并给出进度（如「已练 12 / 32 小节」）；与变速训练器可同时开，谁先到谁停；练满即自动计入练习统计
- **听辨训练**（v1.10）：训练模式区的「听辨训练 · 练耳朵」入口。随机播一段节奏（**不显示题目**），从三张**只给记谱、不给名字**的候选里选你听到的那个，即时反馈；战绩（正确率 / 最高连对）存在本机并显示在入口旁。练的是「听不出附点/切分」这件事本身——此前产品只让人看得见节奏
- **练习统计**（v1.11 起更实用）：练习统计面板除了本周时长/连续天数/速度纪录，还列出**本期练过的节奏型**（场次 · 迷你趋势 · 本期 BPM 区间 · 最后练习于）、**本期没碰的**（并区分"从没练过"），以及**听辨正确率**。日柱图回答"哪天练了"，这块回答"练的是什么、有没有在进步"
- **曲式编排**（v2.0）：预设卡片 → 「编排曲式」。一首歌 = 若干段，每段 = 若干块（一个节奏型 × N 遍）；
  编好后「从头播」走完整结构，「起/终」设范围 + 「范围循环」= 只练副歌，播放中「◀ 上一段 / 下一段 ▶」跳段。
  **整首须同拍号**（混拍号会被拦下并说明是哪段）
- **使用方法**（v2.0.1）：顶栏常驻「使用方法」入口（在状态 chip 之前）。打开是**一页分层说明**——默认只给新用户最需要的三段（三步上手 → 画面怎么看 → 先试这几个开关），点「展开完整说明」再出全部控制项、训练模式、曲式编排、自己画节奏型、数据与隐私、键盘快捷键。新手不必先去翻这份 README
- **变速训练**：训练模式开启后每次播放从起始 BPM 起步，每练满 N 小节自动 +步长爬坡（不打断播放），到目标速度练满一级自动停止；练过即记住进度，「继续上次 · 从 X BPM 接着练」一键接续（v1.4）
- **练习统计**（v1.4/v1.6）：有效练习（≥30 秒）停止时自动入账；顶栏「练习统计」看本周时长 / 连续天数 / 速度纪录 / 累计场次 + 近 7/30 天柱图 + 各节奏型速度纪录，记录可导出 JSON 备份
- **7 天爬升计划**（v1.5）：按当前起始/目标 BPM 一键生成 7 段排程，「开始今日训练」一键开练；练到当天目标自动推进，缺练顺延不补卡
- **后台保活**（v1.4；v2.6.2 起在**顶栏**版本号旁，原在训练模式区）：wakeLock 防息屏 + 静音循环音频兜底（iOS）；默认关，播放中打开立即生效
