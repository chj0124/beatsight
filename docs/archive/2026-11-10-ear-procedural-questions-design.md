# 全拍号随机听辨题设计

> 历史快照 · 已归档。行号与自验数字不作实时依据；修复状态以 `CHANGELOG.md` 为准。

## 意图与范围

把固定三组、实际锁定第 0 组的听辨题库，替换为可无限生成的全拍号随机题。拍号为 `VALID_METER` 的 2、3、4、5、6、7，分别显示为 2/4、3/4、4/4、5/4、6/8、7/4。作答前不显示拍号文字，用户同时辨认节奏与小节结构，作答后揭晓。

用户明确要求：**不得破坏现有边距、间距等布局。**

## 约束

- 不修改 `<style>`、候选 DOM 结构、卡片尺寸、边距或间距。
- 保持单文件、零运行时依赖、无构建与 `file://` 直开。
- 正式答案仍是一小节重复两遍；预备拍跳过、作答、判分、重听、自动停止行为不变。
- 总时值、重音、休止和候选差异必须可校验，不能用无约束随机音符凑题。
- 不提交、不推送；版本在 fetch 后确定。

## 方案比较

1. **固定扩库 + 独立随机**：仍有限且可能连续重复，不采用。
2. **受约束程序化生成（用户确认）**：答案按拍号语法生成，干扰项由受控变异或异拍号生成得到，无限题量且近期去重。
3. **完全独立随机三个候选**：易出现无解题、送分题和不可辨认节奏，不采用。

## 生成与判分设计

- 新增 `makeGeneratedQuestion(rand, options = {})`，返回既有 `question` 结构；`options.meter` 与 `options.kind` 只用于确定性测试。
- `randomPattern(meter, rand)` 使用合法 tick 组成一小节；至少三个非休止发声点，至多一个非首音休止，限制长休止。
- 5/4 使用 2+3 或 3+2；6/8 使用两大拍；7/4 使用 2+2+3、2+3+2 或 3+2+2。
- 同拍号题通过交换相邻时值、拆分、合并或休止变异产生干扰项；拍号辨认题使用不同拍号候选。
- 校验每个候选的总时值、合法时值、非休止发声数和签名唯一性；签名包含拍号、时值、休止和重音。
- 最近 32 个答案去重，重试有上限，失败时回退旧的随机手工组而不是第 0 组。
- 播放播报只说“共 2 小节”，不再提前报拍数；答案名称包含拍号，作答后揭示。

## 验收

批量覆盖全部拍号和两类题目，验证总时值、发声数、重音、候选唯一性、答案在候选内与近期去重；确认 `next()` 不再固定第 0 组且播报不泄露拍号。新增断言须先失败后通过，配反向验证。真实浏览器全量冒烟用于确认现有布局与间距无回归。
