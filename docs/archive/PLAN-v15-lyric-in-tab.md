### 0.1 用户已确认的需求

| # | 决策 |

| R2 | 谱内与回退贴行**沿用同一套行距**，首版不回收谱内模式下空出的下方空间 | 防止按窗口过密回退、无词段切换或跨设备回退时跑道上下跳；本期先解决视线问题，紧凑化另案 |

## 1. 问题定义与事实基线

### 1.1 要解决的问题

现有「贴在每行小节下」只缩短了谱词距离，歌词仍是一条独立阅读轨。大屏上边弹边唱时，
视线需要在六线谱记号与下方字块之间往返。新模式必须让**歌词字与对应节奏位置进入同一视野**，
而不是把独立歌词带再向上移动几像素。

### 1.2 当前实现可复用的部分

- `S.lyricPos` 当前为 `auto|follow|bottom`，默认 `auto`；设置组在 `index.html:4748-4769`，状态加载在 `:7981-7989`。
- `effectiveLyricPos()`（`:11358`）已集中处理 auto、窄屏与连续滚动；连续滚动恒为 `follow`。
- `buildLyricLane()`（`:12648`）已按网格窗口逐行取字，处理分片、预告、循环、跨行延音和空行；歌词的 `{t,dur}` 时间模型无需变化。
- `#lyricLane` 是 `#viz` 的兄弟覆盖层，不需要把歌词节点塞进 `.bar-row`，可继续守住网格 DOM 不变量。
- `placeLaneOverlay()`（`:12926`）已统一完成逐行覆盖定位；`lyricRestX()` 与静止态重落逻辑可原样复用。
- `paintLyric()`（`:13029`）已用歌曲时间 `headBar/headTick` 推进，负责 `played/on`、逐字 `scaleX` 和当前行状态；不应另造谱内播放时钟。
- 六线谱格子带高由 `--cell-h` 统一给出：桌面普通 44px、含逐弦记谱 56px；整行盒高还包含标注带，**不能拿整行高当六线谱高度**。

### 1.3 不能忽略的现有约束

1. 帧内零布局读取：所有文字、记号碰撞测量只能发生在构建/重排阶段。
2. `follow` 的 52/48px 行距补偿同时照顾歌词带和下一行和弦胶囊；不能只按歌词高删改。
3. `buildLyricLane()` 与 `paintLyric()` 共用 `lyricWinBase()` 和重建签名，不能为谱内模式分叉。
4. 连续滚动的歌词与网格共用 `(dx,dy)`；本方案首版仍让连续滚动走 `follow`，不新增第三套滚动语义。
5. 歌词轨还有音高上标与无词独立音符块；切到谱内不能把它们直接隐藏。
6. 运行时零依赖、单文件、`file://` 直开不变；不引入 Canvas 歌词引擎或新排版库。

## 2. 模式定义与状态解析

### 2.1 四种显式/自动位置

| 保存值 | 按钮 | 行为 |
|---|---|---|
| `auto` | 自动 · 窄屏底部 | 完全沿用现状：窄屏 `bottom`，宽屏 `follow`；绝不自动选择 `tab` |
| `follow` | 贴在每行小节下 | 完全沿用现状 |
| `bottom` | 集中在底部 | 完全沿用现状 |
| `tab` | 嵌入六线谱 | 满足入口与内容条件时谱内显示；否则临时按 `follow` 显示，保存值仍为 `tab` |

设置组采用追加顺序：`自动 / 贴在每行小节下 / 集中在底部 / 嵌入六线谱`。
既有按钮顺序和文案不改，减少肌肉记忆与既有测试的无谓迁移。

### 2.2 保存偏好与实际显示必须分开

新增只读运行态，不写回 Store：

```js
lyricViewState = {
  requested: "auto" | "follow" | "bottom" | "tab",
  actual: "follow" | "bottom" | "tab",
  reason: "" | "layout" | "scroll" | "no-tab" | "pitch" | "standalone" | "dense"
}
```

- `requested` 来自 `S.lyricPos` 及 auto 的现有响应式解析。
- `actual` 是本次构建真正采用的布局。
- 回退只改 `actual/reason`，**不得把 `S.lyricPos` 改成 `follow`**；回到适合环境后自动恢复谱内。
- `effectiveLyricPos()` 继续作为稳定入口解析出口；内容回退由另一个布局解析函数承担，避免设置 UI 与渲染各算一份。

建议拆成三层：

```js
requestedLyricPos()       // auto + 显式偏好；scroll 的既有短路保留
canOfferLyricTab()        // 稳定布局条件，决定入口显隐与 tab 是否可实际执行
resolveLyricContentMode() // 当前窗口内容检查，返回 {mode, reason}
```

### 2.3 状态切换结果

| 场景 | 保存值 | 实际显示 | 入口表现 |
|---|---|---|---|
| 桌面宽且适合 | `tab` | `tab` | 显示并选中「嵌入六线谱」 |
| 桌面窄窗口/实际网格过窄 | `tab` | `follow` | 隐藏谱内按钮，偏好保留 |
| 移动端 | `tab` | `follow` | 不显示谱内按钮 |
| 连续滚动 | 任意 | `follow` | 沿用现有限制：位置组禁用并说明 |
| 当前内容不适合 | `tab` | `follow` | 按钮仍保留选中；设置内说明本次回退原因 |
| 显示歌词关闭 | 任意 | 不显示 | 位置组按现状收起 |
| 预设模式/无有效曲式 | 任意 | 无歌词轨 | 不改变位置偏好 |

## 3. 「不开放」与「临时回退」两层规则

### 3.1 入口层：只看稳定布局，不随歌曲时隐时现

`canOfferLyricTab()` 首版同时满足：

1. `narrow() === false`，即视口不满足现有 `max-width:960px` 窄屏条件；
2. `#viz.offsetWidth >= LYRIC_TAB_MIN_W`，首版常量取 **960px**；
3. 不处于连续滚动模式（该模式下整个位置组本来就被禁用）。

说明：

- 不使用 UA、手机型号或 `pointer` 判断设备；平板横屏可以开放，桌面分屏也可能被排除。
- 960 是首版入口阈值，不是“所有歌曲都可读”的保证；真实密度由下一层检查。
- 浏览器缩放会改变 CSS 像素宽度，天然进入同一判据；系统/浏览器只放大字体则由内容测量兜底。
- 入口显隐只由布局变化驱动，不能因为当前歌密一点就消失。

### 3.2 内容层：已选 `tab` 后逐窗口检查

| 条件 | 处理 | 不能采用的做法 |
|---|---|---|
| 当前型无六线层（`vizHasStrum()===false`） | 整窗回退 `follow`，`reason:"no-tab"` | 在节拍跑道上仍声称“嵌入六线谱” |
| `S.pitchNotation!=="off"` | 整窗回退，`reason:"pitch"` | 静默隐藏音高，或把上标压进歌词中央 |
| 当前窗口有 `standaloneNotes`（`row.noteN>0`） | 整窗回退，`reason:"standalone"` | 删除前奏/间奏旋律块 |
| 字与字、字与可见演奏记号不能满足间距 | 整窗回退，`reason:"dense"` | 缩到不可读字号、截字、横向挤压或逐字跳高 |
| 空歌词行、前奏且无独立音符块 | **不回退**；谱内行留空 | 因无词而切换布局或收放行高 |

回退提示复用设置里的 `#lyricPosNote`，按原因显示一条短文案，例如：
「当前谱面过密，暂按贴行显示；仍保留「嵌入六线谱」选择。」
不弹 toast、不打断播放、不每次翻页播报。连续滚动说明优先级最高，覆盖其他 reason。

## 4. 谱内视觉与几何定稿

### 4.1 纵向：固定在六线谱中央

每行歌词的视觉中心对齐该行的格子带中心，而不是整行盒中心：

```text
tabCenterY(i) = rowGeo[i].top + tabBandH(i) / 2
lyricY(i)     = tabCenterY(i) - lyricRowH(i) / 2
```

- `tabBandH(i)` 在结构层从对应行 `.cell.offsetHeight` 实测；桩环境按 `has-pick` 回落 56/44。
- 普通 44px 与逐弦 56px 都走同一公式，不写死 +22/+28。
- `lyricRowH` 首版沿用 28px；`chord-xl` 只影响和弦与既有行距，不把谱内字放大到双关歌词带的 32px 档。
- 字不跟随拨弦点所在弦，不因冲突改变 y；所有字共享一条水平基线。

### 4.2 横向：时间锚点优先，只允许有限右移

歌词初始 x 继续来自 `c.lt/slice` 与现有字内缩公式：

```text
chipX = laneW * c.lt / slice
baseX = chipX + clamp(4px, 25% * chipW, 28px)
```

冲突解决只在一个结构层纯函数里做：

1. 收集本行每个可见 `.strumv`（含空扫、琶音、逐弦）的横向占用区间，左右各加 4px 安全距。
2. 歌词按时间从左到右处理；与记号区间相交时，直接计算“越过该区间后的最小右移位置”，不逐像素循环试撞。
3. 单词/单字右移量上限 `LYRIC_TAB_MAX_SHIFT = 32px`；超过即判本窗过密。
4. 右移后仍需与前后歌词字形保持至少 4px，且不得越过行内容边界。
5. 一次计算后复核全部区间；仍相交即回退，不做第二轮不同规则的漂移。

该函数建议做成纯决策：输入字宽、期望 x、记号区间、行宽，输出 x 或失败。
真实 DOM 只负责提供测量值，单元测试不依赖浏览器排版。

### 4.3 图层与样式

新增作用域类建议：歌词轨 `.lyric-lane.in-tab`，网格 `.lyric-in-tab-on`；不要复用已有 `.tab` 类名。

从低到高的视觉关系：

1. 时值格、拍区、六线底纹；
2. 谱内歌词字及局部线掏空；
3. 拨弦点、品数、技巧字母、扫弦/琶音记号；
4. 主播放头、当前格高亮与弹跳球。

具体要求：

- `.lyric-chip` 在谱内模式下去掉整块底色、边框、发光盒与圆角，`overflow:visible`，不再呈现独立跑道字块。
- `.lyric-row.cur` 不再铺整行歌词底纹；`.lyric-head` 在谱内模式隐藏，避免与主播放头形成第二根绿线。
- `.preview` 的 55% 降权保留；未来歌词仍与未来网格同语义。
- 文字采用局部描边/光晕掏空身后弦线，方向与现有品数“数字断线”一致；不得使用覆盖整格的不透明底板。
- 经典、日间和壁纸背景都要人眼验证描边效果。若文字描边反而压暗/发亮过度，只调整谱内作用域，不改其他模式。
- 字号沿用普通歌词的响应式公式与上限，不为塞入而额外缩字；放不小就是内容不适合。

### 4.4 逐字 karaoke 保留方式

`paintLyric()` 的时间源、`played/on` 状态签名和 `scaleX(0…1)` 写入保持唯一来源：

- 未唱、正在唱、已唱的文字色继续复用现有 token；正在唱仍有绿色强调。
- 谱内 `.lfill` 从整块背景改为当前字下方的 2px 短进度线。
- 进度线左缘与字形左缘一致，宽度在结构层按实际字形测量一次；帧内仍只改 `transform:scaleX()`，不读 `offset*`。
- 字因避让右移时，进度线跟随同一最终 x，不能留在原始 chip 锚点。
- 无词行不画播放头、不画底色的既有规则不变。

### 4.5 行高守恒（首版硬约束）

`tab` 与 `follow` 都挂现有 `lyric-inline-on`，保留 52px / `chord-xl` 48px 的行距：

- 内容过密回退、无词窗口、音高开关前后，除用户主动切到 `bottom` 外，不改变 `.bar-row` 的行顶位置。
- `placeLaneOverlay()` 只在实际 `follow` 时用现有“行盒底+2 / 双关+50”公式；实际 `tab` 时用中央公式。
- `setLyricInlineOn()` 的输入从单一 `follow` 改为 `follow||tab`，但底部/关闭仍摘类。
- `vizClipH()`、`lyricClipH()` 与 `applyVizClip()` 同步核对；谱内歌词不得越出格子带，也不能裁掉最后一行。
- 后续若要回收空白，必须另案证明所有回退路径不会引起播放中跳版。

## 5. 渲染管线与函数级改动

### 5.1 构建顺序

在 `buildLyricLane()` 内保持现有取字和 DOM 数据构建，尾部改为：

```text
取有效曲式与窗口
→ 建 lyricRows/chars/chipEls/fillEls（现有）
→ 解析 requested + 稳定入口条件
→ 若请求 tab：先按候选 tab 落位
→ 结构层一次性测量文字与记号，运行纯布局决策
→ 通过：提交 in-tab；失败：移除候选态并走完整 follow 定位
→ 统一设置 lyric-inline-on、覆盖层盒高与 lyricW
→ 连续滚动静止态仍由 rebuildLyricLane()/buildViz 既有出口重落
```

禁止：

- 在 `paintLyric` / `paintFrameBody` 中做碰撞检测、字体测量或重新选择模式；
- 为回退再次调用公共 `buildLyricLane()` 形成递归；
- 测量与写入逐个交错造成 layout thrashing。应先集中读，再统一写；
- 把谱内歌词节点移进 `#viz .bar-row`。

### 5.2 主要触点

| 位置 | 改动 |
|---|---|
| Store typedef/加载 | `lyricPos` 联合类型加入 `tab`；加载按白名单校验，脏值回 `auto`；热键载荷继续只保存偏好 |
| 设置 HTML | `#lyricPosGroup` 追加 `data-pos="tab"` 按钮；补无障碍名称，不新增 switch |
| `effectiveLyricPos` 附近 | 增加稳定入口解析、运行态与常量；保留 auto/scroll 原行为 |
| `buildLyricLane` | 增加候选谱内构建、内容预检和回退原因，不复制取字逻辑 |
| `layoutLyricLane` / `placeLaneOverlay` | 支持 `tab` 中央锚定与 `follow` 回退；行高规则同源 |
| `paintLyric` | 尽量不改时间逻辑；只让谱内进度线复用既有 transform，谱内播放头由 CSS 恒隐藏 |
| Controls 设置接线 | pill 联合类型加 `tab`；同步入口显隐、选中态和 reason 文案；点击仍走 `Viz.rebuildLyricLane()` |
| `syncAuxVisibility` | 增加谱内入口显隐与回退说明；连续滚动说明优先 |
| relayout/resize | 宽度变化完成后重算候选布局；谱内请求下需要重建测量，不得只改 transform |
| Viz internals | 只读暴露 `lyricViewState` 与必要的纯布局函数，供测试，不暴露可写 Store |

### 5.3 设置入口随实际宽度同步

仅监听 `window.resize` 不足以覆盖侧栏开合、宽屏铺满和主列伸缩。
在装配层新增或复用 `#viz` 的 `ResizeObserver`：回调只同步设置入口和说明，真正网格重排仍走 Viz 现有路径。
回调不引用后方模块，不进入逐帧热路径；测试桩没有 `ResizeObserver` 时由显式 `syncAuxVisibility()` 和窗口 resize 兜底。

## 9. 真实浏览器与人眼验收

### 9.1 冒烟探针 `lyricTabProbe`

至少覆盖：

- 1440 与 1920 宽屏；960/961 边界；“视口 1200、实际 viz 800”的双栏错位场景。
- 普通扫弦、琶音、逐弦多品数、空扫；密歌词、长英文、跨片延音、页末预告。

- 经典/日间、默认壁纸/无壁纸、100%/125%/150% 缩放；resize 后入口与 actual 同步。

### 9.2 必须真人验收

1. 两首示例曲各选含密词、长延音、间奏的段落，确认谱词同视野是否真的比贴行省力。

3. 字的描边/光晕在深浅主题与壁纸上是否清楚，是否误作品数或演奏记号。
4. 短进度线是否足够感知，是否比原整块填充更弱到难以辨认。
5. 谱内模式保留下方空白是否可接受；不可接受也只记录反馈，不在本批临时收行高。
6. 音高/独立音符回退是否容易被理解，提示是否足够且不打断练习。
7. 390px 移动端无谱内入口；从桌面保存 tab 后移动端实际贴行，且现有自动/底部行为不变。

## 11. 风险与回滚

| 风险 | 控制 |
|---|---|
| 谱内字与箭头天然同锚，避让后时间感变弱 | 限制 32px 右移，超出即回退；真人重点验收 |
| 按窗口密度回退导致读法变化 | 整窗统一、行高恒定、设置内说明；不逐行跳变 |
| 描边在壁纸/日间下形成脏边 | 谱内作用域单独调，真实双主题与壁纸验收 |
| 真实字体宽度在桩里不可测 | 纯函数单测＋真实浏览器矩形探针，两层不可互相替代 |
| resize/侧栏变化只移动歌词却不重测密度 | 谱内请求在结构重排中重跑候选决策；帧内不做 |
| 音高与独立音符被新模式吞掉 | 首版显式回退并用测试钉死，不做静默隐藏 |
| 新增跨模块回调破坏 R1–R4 | UI 同步放装配层；若确需新回调，先登记白名单并说明方向 |

回滚粒度：按批次保留可独立 revert 的改动。最坏情况撤掉 `tab` 按钮与候选布局即可恢复原有三种位置；
歌词数据、曲式数据和音频调度不迁移，因此无数据回滚步骤。

## 12. 本期不做

- 不把歌词塞到具体弦线上，不随拨弦弦号上下移动。
- 不做逐字动态纵向避让、自动缩字、歌词省略或横向滚动歌词。
- 不改变 auto 默认，不强制所有大屏用户使用谱内模式。
- 不在连续滚动中启用谱内模式。
- 不在首版实现谱内音高上标或独立旋律音符块；这些场景明确回退。
- 不回收谱内模式下方空白，不重做现有 follow/bottom。
- 不改歌词编辑、时间量化、音高数据、音频发声与调度。
- 不引入新运行时依赖，不把单文件应用改成构建式多文件应用。
