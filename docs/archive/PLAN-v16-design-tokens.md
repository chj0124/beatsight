### 1.3 为什么「再修一轮」不可行（历史轨迹）

审计对注释史的统计：间距类返工 ≥7 轮、居中类返工 ≥12 轮（L281 居中补正、L350 三角没居中、L461–466 轴错位自认、L1261 歌词偏上两轮、L1527 轨道中线高 11.5px、L1850 参数槽偏左……每处注释都记录了「修好又坏」）。结论：**逐处像素补偿在制度上必然复发**——补偿值钉死的是当次快照，任何上游尺寸变化都让它失效，且失效是静默的（无断言把守「为什么是 11.5」）。本方案与既往修补的本质区别：给刻度和对齐立**机器把守的单一来源**，而不是再写一版正确的数字。

## 2. 令牌体系设计（最终形态）

### 2.1 间距令牌（`--sp-*`，4px 网格，按角色命名）

```css
:root{
  /* ---- 间距令牌（PLAN-v16；口径承接设置页 v3.45.4 的「块间 16 / 块内 8」并推广全局）----
     命名按角色不按数值（与 --sel-bg/--veil 的角色令牌文化一致；数值只在定义处出现一次）。
     阶段 3 分批迁移；白名单例外见 §2.5。 */
  --sp-1:  4px;   /* 行内微距：图标↔文字、标签↔控件、并排小元素 */
  --sp-2:  8px;   /* 块内：组内行距、面板内相邻行 */
  --sp-3: 12px;   /* 子组间距：组↔组（卡内）、紧凑块间 */
  --sp-4: 16px;   /* 块间：面板节、分区、卡片头↔内容 */
  --sp-6: 24px;   /* 区块：卡 padding、页面缘、区块间呼吸 */
  --sp-8: 32px;   /* 大区块（编辑器底距等，迁移时按需启用） */
}
```

**收敛映射（D2 甲案）**：`2/3→白名单（光学/字形）`；`5→4 或白名单`；`6→8`（+2px）；`7/9→8`（±1px）；`10→12`（+2px）；`11/13→12`（±1px）；`14→16`（+2px）；`18/20/22→24 或 20→白名单(专区)`；`24/48` 保持。**有断言/探针把守的间距**：收敛值与断言**同一 commit 内同步改**（防「本地绿 CI 红」的历史事故，AGENTS §2）。

### 2.2 字号阶梯（`--fs-*`）

| 令牌 | 值 | 用途 | 吸收现状档 |
|---|---|---|---|
| `--fs-glyph` | 9px | 纯字形（▾/▸ 箭头、rh-3 伪符）——字形例外档，不参与文字层级 | 9 |
| `--fs-micro` | 10px | 装饰性微标：座次尺、区块小签（arg-pick-zone）、diag 标题 | 10、10.5 |
| `--fs-cap` | 11px | 辅助说明/meta/徽标文字 | 11、11.5 |
| `--fs-body` | 12px | 正文、按钮辅文 | 12 |
| `--fs-lead` | 13px | 按钮主文、条目名 | 13、12.5 |
| `--fs-title` | 14px | 卡片标题 | 14、15（15 仅 obs card-title，随 D7 回归） |
| `--fs-head` | 16px | 弹窗标题 | 16 |

显示数字（`.bpm-num` 40 / `.stat-num` 28 / `.bpm-num` 移动 34、36）不进通用阶梯——它们是「读数」不是「文字」，各自声明并注释口径（obs 48/34 的回归归 D7）。半步档并入方向见 D3（建议向上）。**字号改动牵动 ellipsis/nowrap 行为**：每处迁移后跑相关断言（t203 有反向验证脚本 `reverse-verify-t203-preset-typography.js` 盯着排版口径）。

### 2.3 圆角档位（`--radius-*`）

| 令牌 | 值 | 用途 | 依据 |
|---|---|---|---|
| `--radius-cell` | 3px | 时值格族：.cell/.beat-zone/.edcell/.arg-reps/.arg-chd-cell/.arg-pill-tag | PLAN-v11 A5 已归并的既有口径 |
| `--radius-ctrl` | 6px | 小控件：loop-sel、图标钮、条目 hover 块 | 现状 25 处 6px 的多数语义 |
| `--radius-item` | 8px | 条目卡/输入框：preset-item、stat-card、name-input、tr-inp | 现状 24 处 8px 的多数语义 |
| `--radius-card` | 12px | 卡片与浮层壳：card、modal、ed-pop、tg-flyout、**dialog-panel（16→12，D4 一并拍）** | 卡族统一 12 |
| `--radius-full` | 9999px | 胶囊唯一写法（999/99 全部归并，D4） | 多数派写法 |

`50%` 保留（正圆语义：播放键/开关圆点/弹跳球）；1/2px 微圆角（rh-b 等字形级）进白名单。10px 档（tg-flyout/viz-legend/pd-search）→ 12 或 8，逐处按「它更像浮层还是条带」判定并记录取舍。

### 2.4 主题纪律（闸门 R4 的判据）

obs 主题允许覆盖的令牌**仅限颜色族**（--bg/--card/--t*/--green/--veil…既有集合）。**`--sp-*` / `--fs-*` / `--radius-*` 一律不得出现在 `body[data-theme="obs"]` 块**——这条从机制上消灭「两主题各写一份补偿」的 fork（#trainerProg 4px/2px 那类）。obs 的形态个性（pill 矩形化、sec-tag 三件套、数据等宽字体）按 §10.2 的语汇/度量二分法保留。

### 2.5 白名单（登记制，同 R3 控件名登记的先例）

不进令牌、允许保留字面值的情形，逐条登记原因：

1. **光学微调**：负 margin 对齐字面侧 Bearing、`translateY(-1px)` 类（阶段 4 逐个销号前先冻结）；
2. **几何契约值**：六线谱 `--gt:8.6px`、`--yT2:17.2px` 等非 4 网格值（数学推导值，改了破六线谱几何）；
3. **冻结的存量补偿**：阶段 4 台账里尚未销号的条目（销号即出白名单）；
4. **env()/safe-area 计算**：`calc(... + env(...))` 族。

白名单落在 `tools/check-design-tokens.js` 的 `BASELINE` 数据里（工具即台账，不存在第二份要同步的文档）。

## 3. 闸门工具：tools/check-design-tokens.js

**模式：baseline 收缩式闸门**（D5 甲案）——不改任何存量判红逻辑，只拦增量，用「基线只减不增」把存量收敛变成单调过程：

- **R1 令牌存在性**：`:root` 有 `--sp-*`（≥6 枚）、`--fs-*`（≥7 枚）、`--radius-*`（≥5 枚）定义，命名匹配白名单模式；重复定义/未使用令牌报观察项（未使用与 check-orphan-css 职责重叠处，后者优先）。
- **R2 间距增量禁令**：首次运行把 CSS 区段内全部「非令牌引用的 margin/padding/gap 字面值」登记进 `tools/design-token-baseline.json`；此后每次运行比对——**任何新增字面值判红，消失即从基线剔除**。基线行数单调下降 = 迁移进度可直接度量。
- **R3 圆角与胶囊写法**：`border-radius:999px|99px` 一律判红（无观察期，存量迁移是机械替换、风险极低）；其余圆角字面值走 R2 同款基线制。
- **R4 主题纪律**：`body[data-theme="obs"]` 块内出现 `--sp-/--fs-/--radius-` 覆盖或 padding/font-size/border-radius/height 的 px 字面值 → 判红（存量先入基线，D7 甲案执行后清零）。
