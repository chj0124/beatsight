## 2. 批 1 · 数据地基 + 文本语法

### 2.1 数据区常量（L4453–4455）

| 位置 | 现状 | 改为 |
|---|---|---|
| `LYRIC_GRID` | `= T16`（12t） | `= T32`（6t） |
| `LYRIC_BASE` | `= 2 * LYRIC_GRID`（推导式，**P2 的雷**） | `= T8`（24t，独立常量，注释写明「不随 GRID 派生」） |
| `LYRIC_MIN_DUR` | `= LYRIC_GRID` | 不变（随 GRID 变 6t） |

**波及面全量复核**（`grep LYRIC_GRID` 约 15 处，逐处判定）：磁吸 `bestD`（L16860）、字块拖拽吸附（L16971/16979）、「时值±1格」（L17030）、键盘微调步长（L17467）、气泡读数（L16930）、`lyricTip` 文案（L17492「松手吸附 12 tick」→ 按 LYRIC_GRID 现算，**不写死数字**）。字符粘贴 `distribute`（LYRIC_BASE 步进）不受影响——复核确认即可。

### 2.2 `normLyricLine`（L6261–6290）

不改逻辑，只换粒度来源：字与音符的 t/dur 吸附 `Math.round(x / LYRIC_GRID) * LYRIC_GRID` 随常量自动变 6t。**验收口径**：6t 倍数原样过；8t（三连音）被吸附；音高域 `[PITCH_MIN, PITCH_MAX]`、重叠跳过、越界剔除语义逐位不变。`lyricMaxNotes = 512`（L5256）保持——16 小节满铺 32 分正好 512 顶满为极限场景，超限钳制带 warn 不静默，不为假想容量加码。

### 2.3 `parseMelodyTokens` 重写（L4577–4596）

```js
/* token 细分档（P3/P4）：尾部 _ 后缀定档——无后缀=八分(24t)、_=十六分(12t)、__=三十二分(6t)，
   >2 条 = 非法（T64 不开）。音高 / "-" / "0" 三类 token 都可带后缀：
   「5_」十六分音符、「-_」细档延音、「0__」细档休止。步长 = LYRIC_BASE >> k。 */
function parseMelodyTokens(text, keySemi){
  const toks = String(text || "").trim().split(/\s+/).filter(Boolean);
  const notes = [];
  let cursor = 0, lastNote = null;
  for (const tk of toks){
    const us = /_+$/.exec(tk);
    if (us && us[0].length > 2) return { notes: null, bad: tk };
    const k = us ? us[0].length : 0;
    const step = LYRIC_BASE >> k;                 // 24 / 12 / 6
    const body = k ? tk.slice(0, tk.length - k) : tk;
    if (body === "-"){ if (lastNote) lastNote.dur += step; }
    else if (body === "0"){ lastNote = null; }
    else {
      const m = matchPitchSuffix(body, 0, keySemi);
      if (!m || m.len !== body.length) return { notes: null, bad: tk };
      const n = { t: cursor, dur: step, p: m.p };
      notes.push(n); lastNote = n;
    }
    cursor += step;
  }
  return { notes: notes, bad: null };
}
```

非法 token 仍整句不落（半句谱比没有谱更难排查——现有纪律，L4573 注释原文）。`matchPitchSuffix`（L4507）零改动——后缀剥离在其外层完成。

### 2.4 `melodySerialize` 重写（L4602–4615）

现规则「`n.t - cursor` 不是 LYRIC_BASE 整倍数就跳过」在 6t 世界上会丢一切 32 分细节——重写为**贪心分档**：

```js
/* 无损往返（P5）：gap 与 dur 都按 24 > 12 > 6 贪心分解。
   · 音符本体 = 不超过 dur 的最大档（24 无后缀 / 12 "_" / 6 "__"），余数用细档延音补：
     dur=36 → "5 -_"；dur=18 → "5_ -__"；dur=30 → "5 -__"；dur=42 → "5 -_ -__"
   · 空档 = 细档休止序列：gap=18 → "0_ 0__"（12+6）
   · 非 6t 对齐或非递增的脏值跳过（norm 后不出现，防御位）
   不变量：parse(serialize(notes)) ≡ notes（6t 对齐 · 升序 · 不重叠时）——T224b 属性断言锁死。 */
```

**回归护栏**：纯 12t 对齐的旧谱，输出与旧版逐位一致（不无故掺 `_`）——序列化只在该细的地方细。

### 2.6 简谱正字法显示（P12 · 显示层，随批 1 交付）

**双形态分工**（关键设计：**文本形态一根手指都不动**，正字法是显示专用第二形态）：

| 形态 | 内容 | 服务对象 |
|---|---|---|
| 文本形态（不变） | `jianpuOf` 的 `1'` / `6,` / `#4`；音名档 `pitchNameOf` 的 `C5` / `D#4` | serialize 回填（P5 无损往返）、贴谱 prefill、aria-label、announce——t222 既有 11 条字符串断言原样绿 |
| 正字法形态（新，**仅简谱档**） | `jianpuParts(p, keySemi)` → `{acc, deg, octUp, octDown}`（纯函数，internals 导出可单测）+ `mkJianpuGlyph(parts)` 建点号节点（只建点号，无时值线） | 主视图 / 编排页的**可视**标签（nm 档直接用文本形态，不进 glyph） |

**正字法规则（两轮收敛后的最终形态：只补点号）**：

| 项 | 实现 |
|---|---|
| 高八度 = 数码上方点，每高一个八度加一点（竖排堆叠） | `.jp-g .jp-dots.top`，`textContent = "·".repeat(octUp)`，绝对定位数码正上方 |
| 低八度 = 数码下方点（竖排堆叠） | `.jp-dots.bot` 同构（`octDown`） |
| 升降号 = 数码前 `#`（升号制，b7 同音异名归一） | 前缀文本节点，`jianpuOf` 同口径 |
| ~~时值下划线~~ **不画**（两档都不画） | 时值由块宽（与 dur 严格成正比）+ `−` 延音上标 + 灰色休止块表达，已是可视化载体；现实简谱画下划线是因为纸上无其他时值线索，此处再画是第三遍冗余且小字号必糊（R9 减半） |
| 音名档（nm） | 保持 `C5` / `D#4` 文本形态原样显示，不加任何标记（音名体系的八度就是数字，无点号传统） |

**接线点（显示四处换 glyph，其余全部保持文本）**：主视图字上标（L10986）、主视图 notechip（L11015）、编排页 notechip（L18668）、编排页字上标（L17449 / L17717）；多单元 mark（一字多音）每单元独立 glyph、`·` 分隔符保留为文本节点；tie 单元 `-` 保持文本。**不换**：aria-label / title / announce / serialize / 音高组按钮读数（L18266，按钮空间小点号易糊）。

**CSS**：`.jp-g{display:inline-flex;flex-direction:column;align-items:center;line-height:1;padding:3px 0}`；`.jp-dots{font-size:.8em;line-height:.7}`；主视图字上标（约 11px）上下各预留 3px 防点号压字 / 裁切（字块 chip 的 `overflow:hidden` 裁剪口径复核，t101 同款 CSS 文本断言）。

### 3.3 拖拽（新纯函数 + 轻量绑定，**不复用字块 bindDrag**）

字块 `bindDrag` 深度耦合字语义（换位 / dur 钳制 / 字锚点即时音），音符硬塞进去两边都变脆。另立**平行的轻量实现**，共享模式而非共享代码（阈值两段式转正、`setPointerCapture` 防御包裹、气泡 / ghost 建-摘同 guide 模式——这些是模式复用，不是函数复用）：

```js
/** 音符拖拽落点（单事实源）：段界钳制 [0, span - dur] + 节奏型 onset 磁吸（与字块同锚点表、
    同半拍优先口径）+ 6t 格吸附 + 邻音重叠预检。
    @returns {{t:number, blocked:boolean, blockerIdx:number}}
    blocked = 落点与既存音符重叠 → 调用方 announce 拒绝（P8：不自动挤、不静默吞）。 */
function noteDropTarget(notes, q, span, rawT, onsets){ /* 纯函数，导出可单测 */ }
```

- **气泡读数**：`第 ⌊t/barTicks⌋+1 小节 · 第 ⌊t%barTicks/TPB⌋+1 拍 · 时值 ⌊dur/6⌋ 格`（格式与字块气泡 L16930 同族）。
- **松手提交**：`blocked` → announce（「与第 N 颗音符重叠——旋律音符互不重叠，先挪开它再试」）且 Store 零变化；否则 `lyricCommit(arr, sec, line.chars, { notes: newNotes })` → `arrangeRender` → selNote 存活。
- **无换位、无 grip**（P7/P9）；32 分块（6t ≈ 拍宽 12.5%）拖拽命中天然成立，但**键盘是精度主路径**（R4）。

### 3.4 键盘（keydown，L17463 字块同款三行式）

| 键 | 行为 |
|---|---|
| ← / → | t ∓ `LYRIC_GRID`（6t），段界钳制 + 邻音重叠预检（同 3.3 口径，撞上拒绝 + announce） |
| Shift + ← / → | dur ∓ `LYRIC_GRID`，钳 `[LYRIC_MIN_DUR, 段尾 - t, 前向邻距]` |
| Delete / Backspace | 删单颗（P10）：splice → `lyricCommit({notes})` → announce「已删除，可撤销」 |
| 每击键 | = 一步 undo（V2 粒度纪律，t225b 断言） |

提交统一走 `lyricCommit` 的 `opts.notes`（L17334，B 期已支持）：no-op 判定、行级快照、redo 清空全部免费获得；**cue 不响**（`lyricCueNow` 是字锚点音，旋律轨无即时音——B 期已是纯显示轨）。
