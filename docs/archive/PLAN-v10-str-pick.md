## 0. 拍板记录（定稿，不再开放讨论）

| 项 | 定稿 |

| 视觉纪律 | 遵循既有设计风格：复用 `.strumv` 家族的色板与染态（currentColor / hit 绿 / ghost 空心 / 预告淡显），不新增颜色令牌；点径 ≤ 弦距 |

## 1. 需求与场景

民谣弹唱的分解和弦伴奏（53231323 家族）：把一拍拆成若干八分/十六分音，每颗拨一根
（偶尔多根）弦。现状节奏型的最小单位是"一次扫弦手势"（zone 三档只是弦组滤波），
无法表达"这一格拨第几弦"。本方案把最小单位细化为"一次拨弦事件，可指定弦与（可选）品"。

覆盖场景：
- 常规分解：T3231323 家族（根音弦随和弦在 ④/⑤/⑥ 间选择，str 记绝对弦号天然覆盖）；
- 双音变体（根-3-2-(3+2)）：一格多弦；
- 加花 / 低音经过音（bass run）：指型外音以 `{s, f}` 逐格标注，跑道显示品数；发声与常规单弦格同款（声音只分单拨/齐拨，不还原音高——音位信息全在显示层）；
- 技巧记号（H 击弦 / P 勾弦 / S 滑音 / O 泛音）：逐弦挂 `tech`，跑道在点旁标字母——覆盖指弹谱面"有声但右手不拨"（H/P/S）与"触弦方式不同"（泛音）的动作语义；
- 转位和弦（G/B）：和弦文本标注照旧，`str` 根音换弦即可，零额外机制。

不覆盖：指弹的多声部建模（各弦独立延音是乐器物理不是手部动作，不归节拍器管）、
品位自动推导、打板/拍弦。概率判断：指型外音位在典型弹唱曲目的小节占比 <5% 且集中
在衔接处——故品号/技巧都是**可选增强**，不是必填义务。

## 2. 数据模型

```
step = { t, rest, dir?, zone?, str? }
str  = [{ s: 1–6, f?: 0–24, tech?: "H"|"P"|"S"|"O" }]
       // 按 s 升序、去重、非空；f 省略 = 不标品号；tech 省略 = 普通拨弦
       // H 击弦 / P 勾弦 / S 滑音（有声但右手不拨）/ O 泛音（触弦方式不同）
```

- 与 zone 正交、存在即覆盖：`str` 存在时渲染与发声都以它为准，zone 失效（编辑器里 zone 行显示被覆盖态）；无 `str` 一切照旧。
- 校验口径照 dir/zone 惯例：脏值（s 越界/重复/空数组、f 越界/非整数、tech 不在白名单）**静默降级省略**，不牵连整型；Σt = meter×TPB 的小节校验不受 str 影响；**rest 格上的 tech 静默抹除**（与"休止符上的 dir 被抹掉"同先例——无声的技巧无从谈起）。不做音乐语义校验（如"H 必须有同弦前音"不查，同 dir 不查上下游的先例）。
- onset / 锚点语义不变：一格无论几弦、带不带技巧，**一步一条 onset**（锚 = step 起点）——播放头、弹跳球、歌词一键对齐（t115 契约）零改动。

登记点（一处加字段、N 处登记）：
1. `Step` typedef（index.html:6057）+ customs 内联类型（:7625）——tsc 守门；
2. `validatePreset`（:7974–7991）——str 白名单校验；
3. `packPreset`（:7921）——导出字段唯一写点（t217 守两份清单一致）；
4. `demoPresetEq` 规范化（:5849–5857）——示例曲比对要带上 str；
5. 编辑器 `barFinger`（:17090）——行缓存键含 str，漏了缓存命中脏渲染。

### 2.1 常量与归一化（共享区，判据同源）

新增常量与函数放在共享区（`strumDirCls` :6227 / `arpGlyph` :6208 一带），Store / Viz / Editor / AudioEngine 四方共用——
「渲染判据与发声判据逐字同源」的铁律靠"只有一份函数"而不是"抄写一致"来守：

```js
const STR_S_MIN = 1, STR_S_MAX = 6, STR_F_MAX = 24;
const VALID_TECH = ["H", "P", "S", "O"];   // H 击弦 / P 勾弦 / S 滑音 / O 泛音（定稿，不再开放）

/** 归一化 str 字段：合法 → 升序去重后的新数组；全脏/空 → undefined（= 没这个字段）。
    逐条静默降级（某条脏只丢那条），rest 格上的 tech 在这里抹除（与"休止符上的 dir 被抹掉"同先例）。 */
function normStr(raw, isRest){ /* 过滤 {s:1–6 整数} → 去重排序 → f 钳整数 0–24/省略 →
     tech 白名单/省略 → isRest 时删 tech → 空数组转 undefined */ }
```

调用点：`validatePreset`（加载/导入）、编辑器写入路径（面板与铺设框的产出先过它再落草稿）、
`demoPresetEq` 规范化。**渲染与调度读到的 str 一律是 normStr 的产出**，不再各自防御。

### 2.2 hasStrum 判据扩展（本次最容易漏的一处）

现行 `hasStrum(pat)`（判断"这个型带扫弦记谱"）只看 dir/zone。纯分解型（全部格只挂 str）
在原判据下：六线层不建、扫弦声部不进、歌词锚点退回拍点——三处同时错。故判据扩展为：

```js
const hasStrumLike = s => s.dir !== undefined || s.zone !== undefined || !!(s.str && s.str.length);
```

受影响面（全部改走这一个谓词，逐字同源）：`.tab`/`.strums` 层构建（buildRowLayers :10966）、
发声声部路由（schedOneStep :13826）、歌词锚点（secOnsetTicks :19145 的 hasStrum 分支）、
strumGrid 补拍（:13866）。t240b/d 各钉一条"纯 str 型"断言。

## 3. 可视化设计（遵循既有风格）

跑道本有六条弦线（`.tab` 渐变层，几何变量 `--gt:8.6px` / `--gtop:0`，线落 0/8.6/17.2/25.8/34.4/43px），
扫弦箭头按弦区跨纵距。分解记号顺着这套骨架长：

- **拨弦点**：共享函数 `pickGlyph(host, str)`（与 `arpGlyph` :6208 同款模式，createElementNS 建 SVG）。
  单弦 = 对应弦线纵位一个实心圆点；多弦 = 同一 x（格中心，与箭头同定位公式）纵列多点。
- **品数**：`f` 存在时点内（或点右）标数字——这就是六线谱"弦上数字 = 品"的百年记法，不发明新语言。
- **技巧字母**：`tech` 存在时与品数合并为一个文本串放点的右侧（`3` / `3P` / `P`），
  不另开"点上方"位置——多弦纵列时上下文字会互撞，右侧串是六线谱里 `3P` 的既有写法。
  H/P/S 的语义是"右手不拨"（与空扫互为镜像：空扫 = 手动无声，击勾滑 = 有声手不动），
  视觉上仍画实心点（它有声），靠字母区分动作归属。

### 3.1 pickGlyph 结构与几何（SVG 细化）

- **宿主复用 `.strumv` 类**：`div.strumv.pick`（+`.ghost`），`data-i` 记格子下标，水平定位
  `left = (startT + t/2)/barTicks%` 与箭头同公式。这样 setCell 的 `.hit` 切换（:13284）、
  预告行淡显、窄格 STRUM_MIN_W 门**全部自动继承**，帧内零新增逻辑（PROBE 零布局读取不破）。
- **SVG**：`pickGlyph(host, str)` 建 `viewBox="0 0 26 46"` 的 SVG（固定像素系，不像 arp 那样拉伸——
  点永远对着六线全高）。弦号→纵位：`cy(s) = (s-1) × 8.6`（① 在最上 y=0，⑥ 在最下 y=43，
  与 `--gt`/`--gtop` 及 kT/kB 的既有跨距口径一致）。
- **每条 str 条目**：`<circle cx="5" cy="…" r="3.4" fill="currentColor">`；有 f/tech 时
  `<text x="10.5" y="cy+2.6" font-size="7.5" fill="currentColor">3P</text>`（opacity .85）。
- **ghost（rest+str）**：circle 改 `fill:none;stroke:currentColor;stroke-dasharray:2 2`，
  颜色由 `.strumv.ghost` 的既有蓝色规则染色（CSS 管色，SVG 只管形）。
- **hit**：`.strumv.hit` 的既有变绿规则染色（`fill:currentColor` 继承），无需新规则。
- **染态**（照抄 `.strumv` 三套）：播放 `.hit` 变绿；空拨（rest+str，手到无声 = 闷音/虚拨记法）= 空心点
  （对应 ghost 蓝虚线语义）；预告行淡显。CSS 挂在 `.strumv` 家族邻近（:1025–1100），
  特异性链遵守 :1066–1082 的既有层级。
- **三处渲染点同改**（防漂移铁律）：主视图 `buildRowCells`（:11141–11163）、编辑器 `editorRender`
  （:17189–17206）、编排页 `mkPatBar`（:19297–19306），共用 `pickGlyph`。
- **窄格降级**（沿用 `fitCellAnnotations`/`STRUM_MIN_W` 两阶段门）：先藏品数数字与技巧字母（只留点），更窄再藏点。
- 不动的：格子填充 `--f`、座次尺、时值标注、弹跳球（读 onset 表，与格子零耦合）、歌词轨。

## 4. 编辑器设计

- **弦/品/技巧面板**：选中格子后，方向/弦区行旁新增六行迷你面板（⑥→① 各一行）：
  每行 = 启用开关 + 品数输入框（0–24，留空 = 不标）+ 技巧循环钮（无 → H → P → S → O → 无）。
  只启用不填不选 = 普通分解点；填品数 = 加花点；选技巧 = 技巧点。
  格子带 `str` 时 zone 行显示被覆盖态（灰 + hint「逐弦优先」）；清空全部弦自动回到 zone 可编辑。
- **按序铺弦号**（小节级）：输入框接受空格分词，语法 `s[:f][tech]`——`5`（裸弦）、`5:3`（带品）、`2:0H`（带品带技巧）、`3P`（无品带技巧）均合法（如 `5:3 3 2 3 1 3 2 3`），
  按顺序铺到本小节的**发声格**（rest 格跳过）；颗数不匹配 → 报错不写入（不写半截）。
- **交互纪律照现有**：pushUndo 先行、同态重按不推栈、aria-pressed 与高亮收口在
  `editorRender` 末尾同一处（:17279–17303）；aria-label 拼「⑤弦3品勾弦」（:17178–17180）。
- 撤销栈/试听/保存零改动（JSON 快照与深拷贝天然带新字段）。

## 5. 发声设计

**声音只有两种，判据 = 这一格拨了几根弦**（与弦号、品号、技巧无关——三者都是纯记谱，不进发声路径。H/P/S 的音仍按单弦出声：它确实有声，只是不出自右手；时机提示不丢）：

| | 单弦（str 长度 1） | 多弦（≥2） | 无 str（老数据） |
|---|---|---|---|
| 路径 | 新增 `pluckHit(t, peak)` | 既有 `strumZoneHit` 全扫口径（双频段叠加，不按弦组范围细分） | 既有 zone 逻辑 |
| 音色 | **一种固定的拨弦音**：所有单弦格同参数——同一弦同一品与不同弦不同品听起来完全一样 | 扫弦频段噪声（与现行全扫一致） | 不变 |
| 声部 | `S.strumVol`（扫弦声部），峰值钳制与 latOff 纪律照旧 | 同左 | 同左 |

- `pluckHit` 合成：振荡器 + 指数包络 + 短噪声激励（拨片感），骨架复用 `kickHit`（:13511）/
  `noiseHit`（:13492）；**无频率参数**（定值，与 click 的频率档常量同待遇）；每格 3–4 节点，
  命中即建不池化（量级与现有 click 同级，240BPM 三十二分后台窗测算内）。
- 调度：`schedOneStep`（:13826）加 str 分支——单/多弦各**一次**调用、**一条 onset**；
  swing/静音拍/层级留在 step 级。`strumGrid` 补拍逻辑（:13866–13872）不变。
- 「渲染判据与发声判据逐字同源」铁律（:13829 注释）适用于 str：三处渲染点与调度共享同一判据函数。
### 5.1 pluckHit 配方与调度分支（伪码定稿）

```js
/* 固定拨弦音色（无频率参数——定值与 click 的频率档常量同待遇）：
   体音 triangle 392Hz 快速下沉到 196（kickHit 式拨弦感），attack 4ms / decay 180ms；
   触弦噪声 noiseHit(2600Hz, Q=2, 30ms, peak×0.35)。合计 4–5 节点，与 click 同级。 */
function pluckHit(t, peak){ /* osc(triangle, 392→196) → Gain(exp 包络) → masterGain
                               + noiseHit 激励；t 的 latOff 补偿沿用 playClick 入口口径 */ }

/* 调度分支（schedOneStep）：str 优先于 zone；声部判定与 playClick 逐字同源——
   收口为一个共享谓词 stepVoiceOf(step)，两处都调它，不各自展开 */
const v = stepVoiceOf(step);   // {voice:"strum", kind:"pick1"|"pickN"|"zone", zone}
// kind: str 长度 1 → pick1（pluckHit）；≥2 → pickN（strumZoneHit 全扫口径）；无 str → zone 照旧
```

- onsetBuf / swing / 静音拍 / accents 层级 / strumGrid 补拍：全部不变（onset 仍一步一条）。
- `dir:"A"` 与 str 共存时各管各的（A 是记谱，str 管弦）——第一期无交互。
- 设计理由（用户口径）：声音是**手序提示**（单拨/齐拨的对比足以听出 53231323 骨架有没有跑偏），
  不是音高还原——与现行扫弦声"zone 只模拟明暗、不当真和弦"同一哲学。

## 6. 不变量与禁区（动手前再读一遍）

## 9. 风险

- 窄格点的可读性（K=2 十六分密排）：先藏品数再藏点的两级降级兜底，真机复核；
- 节点成本：多弦格走既有全扫口径（固定双频段、两颗脉冲），成本与弦数无关；单弦 `pluckHit` 与现有 click 同级——整体无新增量级，冒烟实测一轮兜底；
- 编辑器六行面板的纵向空间（每行三件控件：开关 + 品数框 + 技巧钮）：窄档堆叠时注意别顶破编辑器布局（参照 ctl-pills 折叠先例）。

## 10. 边界情形清单（实施时逐条过）

1. **纯分解型**（全部格只有 str、无 dir/zone）：hasStrumLike 扩展后六线层 / 扫弦声部 / 歌词锚点 / 补拍四处同时成立（t240b/d 钉死）——漏扩展时三处同错，是本次最高危单点。
2. **rest+str（空拨 = 闷音/虚拨记法）**：无声、无 onset、空心虚线点；tech 在 normStr 里抹除。
3. **一格 6 弦**：纵列 6 点各自带文本串（不同 cy 不互撞）；发声仍是全扫口径一次调用。
4. **老版本应用导入含 str 的导出包**：validatePreset 白名单静默丢弃 str（既有降级惯例）——可接受的向后兼容，写进 DEVELOPMENT 数据格式节。
5. **scroll / 分页两模式**：glyph 只依赖行内几何，与模式无关；scroll 下 K=1 不变。
6. **REDUCE_MOTION**：无新增动画，天然合规。
7. **PROBE 帧内零布局读取**：glyph 只在结构层构建；帧内对 pick 的唯一操作是 setCell 的 `.hit` 切换（继承既有路径）。
8. **编辑器试听**（previewRef = draft）：新字段经 editorRender 同源渲染，试听所见即保存所得。
9. **歌词轨**：字块布局/着色不读 str；锚点（secOnsetTicks）把 str 格当发声格（与扫弦格同口径），一键对齐行为不变。
10. **停机/预备拍**：resetForStop 摘 `.hit` 的既有路径覆盖 pick 宿主（同 .strumv 类）。
