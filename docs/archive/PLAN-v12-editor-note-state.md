## 1. 背景与问题

### 1.1 文案困境的三轮收敛（为什么是「两组开关」）

1. **原始问题**（用户图一反馈）：悬浮窗「发声 休止」想表达两种情形——真空休止、不触弦但前音延续——但「休止」一词只覆盖前者。
2. **第一轮反例**（用户）：改「触弦/不触弦」也不对——**触弦也可以止音**。触弦既可能发声也可能休止；不触弦时可能仍在发声（余响）也可能没声。单一物理动作轴命名不通。
3. **第二轮反例**（用户）：「余音未尽则延续，否则休止」是循环引用——**谱面上判断余音尽没尽的标记，正是我们正在讨论的这个标记**。它不是对声学状态的描述，而是余音问题在谱面上的唯一落点；应用侧既无延音也无止音字段（首屏图例 v3.1.0 口径：「弦上的余音是否延续由你的演奏决定……应用只管哪一刻该出手」）。
4. **收敛**（用户提案）：不再用一句话解释，改为**把状态本身摆出来**——`实扫 / 空扫 / 发声 / 休止` 四个词恰好是一个 rest 位 × 方向有无的完整命名，每词只在它那格里有意义，无需解释性从句。

| | 无方向 | 有方向 |
|---|---|---|
| rest=false | 发声 | 实扫 |
| rest=true | 休止 | 空扫（现状：≡ rest+dir） |

### 1.2 两个顺带的问题

- **块库休止符只有四分一种**（PALETTE 末项 `{t:48, nm:"休止符", rest:true}`，index.html L5029）：想造八分/十六分休止做不到，且用它**替换**非四分音符会破坏小节时值——这正是 v2.45.0 造 rest 开关时要绕开的坑（L4001-L4006 注释自认）。删掉后分工干净：**块库管形状（时值），悬浮窗管状态（发止/实空）**，能力是现状的严格超集。
- **编辑器音符块中间的小箭头**（用户图二反馈；第 1/4/5 块 = 非休止带方向的块）：`.ed-strum` 的 ↑↓ 文字字形（L17851-L17856），是 v2.74.0 引入主视图同款 `.strumv` 大竖箭头时刻意保留的旧字形。大箭头已完整表达方向，aria-label 兜底读屏，小箭头纯冗余。

## 2. 设计定案

### 2.1 状态模型（零迁移方案）

新增可选字段 `air:true`，**只在 `rest===true` 时有意义**；空扫判据统一为 `rest && (dir || air)`。

| 数据形态 | 语义 | 轨道记号 | 老数据 |
|---|---|---|---|
| rest=false（±dir/zone/str） | 发声 / 实扫 | 实心箭头（现状） | 不动 |
| rest=true + dir | 空扫（带方向） | 蓝虚线箭头（现状 ghost） | **不动，零迁移** |
| rest=true + air（新） | 空扫（无方向） | 无头蓝虚线杆（新） | 新能力 |
| rest=true（其余） | 休止 | 无记号（现状） | 不动 |

### 2.2 两组开关的耦合规则（点击语义）

| 点击 | 数据变更 | 说明 |
|---|---|---|
| 「休止」 | `rest=true`（dir/air 原样） | 既有行为不变 |
| 「发声」 | `rest=false`，**删 air**，dir 保留 | 空扫翻回实扫，既有行为不变 |
| 「空扫」 | `rest=true, air=true`，dir 保留 | 有 dir → 带箭头空扫（保持 v2.45 既有结果）；无 dir → 新的无方向空扫 |
| 「实扫」 | **删 air**；若 rest 且有 dir → **连 dir 一起删** | 休止格上的 dir 就是空扫记号，留箭头就不是实扫；结果 = 普通休止 |

- 同档重按不推撤销栈（与 dirRow/zoneRow 同一纪律，L18044-L18058 先例）。
- `#airRow` 选中态 = `rest && (dir || air)`；`#restRow` 选中态 = `rest`（现状）。
- 格子带 `str` 时 airRow 禁用 + hint（镜像 zoneRow「逐弦优先」口径，L17945-L17947）；空拨（rest+str）由 restRow 表达，既有。
- **不做「两组操作同一个位」的困惑**：两组开关操作的是**不同字段**（restRow 翻 rest；airRow 写 air/清 dir），上面的耦合表就是全部分支，无重叠路径。

### 2.3 无方向空扫的轨道记号（零新增轨道 CSS）

渲染 class = `"strumv " + kz + " ghost air"`——**不带 dn/up/arp 类**。原理：箭头三角（`.strumv::after`）只由 `.dn/.up` 规则着色定位（L1081-L1084），无方向类则三角天然不可见；杆身虚线沿用 `.strumv.ghost::before`（L1090）；v3.31.2 的 `.hit.ghost` 纵深防御（L1116-L1119）因携带 ghost 自动覆盖。`air` 类本身**无 CSS 职责**，仅作测试断言锚点与自文档。

- 弦区跨距：沿用 prevZone 规则（空扫沿用前一记实扫的 zone，不更新 prevZone）——三处渲染点同口径。
- 主视图走 `.strums` 层并遵守 data-i 槽位纪律（L11520-L11521：strums 数组必须与格子逐位同构，else 分支推 null）。
- 磁吸落点集（L19365，v3.33.22 起含空扫）判据扩展：`rest+dir` → `rest&&(dir||air)`。
- 图例（L3752）补一项：「蓝虚线杆 = 无方向空扫」；`.vl-air` 小示意块加无头变体（L594-L603 同式，去 ::after）。

### 2.4 悬浮窗呈现与提示语（人眼验收项）

- `#restRow` 保留 id，改两 pill：`[发声 | 休止]`（data-rest="off"/"on"）；aria-label「发声开关（发声/休止）」不变。
- 新增 `#airRow`：`[实扫 | 空扫]`（data-air="off"/"on"）+ `#airHint`；aria-label「空扫开关（实扫/空扫）」。
- DOM 预算：airRow 约 +5 节点，块库删休止符项约 −6 节点，净约 −1；smoke 实测为准。

提示语草案（四态 × 两行；「· 点击翻为…」句式沿用现状）：

| 状态 | 行 | 文案 |
|---|---|---|
| 发声 · 无方向 | restRow | 发声中 · 点击翻为休止（方向与弦区保留） |
| 发声 · 有方向 | restRow | 发声中 · 点击翻为休止（已有方向即成空扫） |
| 休止 · 无 air | restRow | 休止中 · 点击翻为发声 |
| 休止 · 有 dir | restRow | 空扫中 · 点击翻为发声 |
| 发声 · 有 dir | airRow | 实扫中 · 点「空扫」翻为空扫（方向保留为箭头） |
| 发声 · 无 dir | airRow | 实扫中 · 点「空扫」即成无方向空扫（一并转为休止） |
| 空扫（任意） | airRow | 空扫中（手过不触弦）· 点「实扫」转为普通休止 |
| 休止 · 无 dir | airRow | 休止中 · 点「空扫」标记手部虚扫（不出声、不触弦） |

### 2.5 软选中（追加后自动选中）

`edSel` 加瞬态 `auto` 标记（不序列化、不进渲染 key）：

- palette 点击：`edSel && !edSel.auto` → **替换**（现状）；否则 → **追加**并软选中新块（grp=3 组块选首块）：`edSel = {bar: editBar, idx: 追加前 length, auto: true}`。
- 单元格手动点击（L17646-L17647）→ 写 `edSel` 不带 auto（清除软态）；轨道空白点击 / 换小节 / 删除 / 撤销 → 清选中（既有路径不动，L17654/L17657/L18038/L18221）。
- `paletteTitle`：仅**手动**选中显示「替换」语义；软选中显示「追加」——保证「连点追加」流不被切成替换流。
- 悬浮层跟随软选中（`syncEdPop` 现状行为）——这是「追加 → 翻空扫」两步流的关键。
- 「追加休止」新路径 = 追加音符块（自动软选中）→ 悬浮窗点「休止」：两步，取代原一步（原一步只能造四分休止且替换路径会崩时值）。

### 2.6 音频与分类

- `air` 纯记谱层字段（同 dir/zone），**scheduler 不读**——发声零影响，孪生型测试钉死（仿 t114e）。
- `stepHasStrumLike` 纳入 air → 纯 air 型归入「扫弦」类（六线层 / 扫弦声部 / 歌词锚点口径，同 v3.47.0 str 收编先例，L6564-L6571 注释更新）。
- 导入白名单（L8355，唯一入口）：`air` 仅在 `rest===true` 且值为 true 时保留，否则静默降级省略（同 dir/zone 口径）；老版本应用导入含 air 的导出包时整体丢弃 air（同 str 先例，可接受，白名单注释写明）。

1. 施工前：`node tools/write-lock.js --acquire "plan-v12 施工"`；`git status --porcelain` 为空；`gh api .../commits/main --jq .sha` 对齐本地 HEAD。

### 8.1 追补：两组开关改为**两轴独立**（覆盖 §1.1 / §2.2 的耦合定稿）

初版按 §2.2 耦合表实现（空扫 ⇒ 自动休止；点「发声」把空扫带成实扫）。用户实测后指出：
**空扫 ≠ 休止**——空扫是「手过弦不触弦、前音可能仍在延」，休止是「手也不动」，二者不是同一状态，
不该由一条轴互相决定。故改定为两条**互相独立**的轴：

- `air`（实扫 / 空扫 = 手部动作）与 `rest`（发声 / 休止 = 这一格出不出声）互不决定，四种组合都合法：
  发声+实扫（普通扫弦）/ 休止+实扫（切音）/ 发声+空扫 / 休止+空扫（原「空扫」）。
- `restRow` 只改 `rest`、`airRow` 只改 `air`、`dirRow` 只改 `dir`，三组各动自己那一位。
- 渲染由 `air`（+ `dir`）决定虚实，与 `rest` 无关；弦区沿用 prevZone（`air` 不更新）。
- **数据兼容**：`air` 显式为布尔则以其为准（`false` 也保留，供「实扫+休止」往返保真）；
  `air` **缺省**时对老数据推断——旧模型「休止 + 方向」= 空扫 ⇒ 补 `air=true`。
  编辑器一旦造出「休止 + 方向」即把 `air` 落成显式 `false`（默认实扫），保证导出/再导入不被误读。
  模板源数据（示例曲 demoBar / 《我们》Q1–Q4）已显式带 air。
- 由此**附带修一个真实缺陷**：编辑器行缓存指纹 `barFinger` 漏了 `air` → 改「实扫/空扫」后缓存命中、虚实不刷新。
- `#airRow` 行首标签取 **「手部」**（与上一行「发声」并列，示意「手部动作」这条轴）。
