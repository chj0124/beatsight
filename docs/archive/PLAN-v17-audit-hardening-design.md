# 守约束审计整改设计（PLAN-v17）

> **状态：历史快照 · 已落地**。施工基线为 `main @ 7b49ca9`、应用 v3.58.9。
> 本文记录已拍板的【守约束】路线；最终落地状态与实测数字以 CHANGELOG 和命令输出为准。

## 1. 目标与非目标

### 目标

1. 修复 Service Worker 缓存生命周期与 PWA 安装异常路径。
2. 修复反向验证入口的误选、误分类、负数计数和已确认老化锚点。
3. 消除共享区架构盲区，并降低 `Arrange` 歌词历史与其他状态机的耦合。
4. 为冷键写入与调度热路径补可测证据；只在证据支持时改变实现。
5. 让发布检查严格覆盖源码、构建产物和两条在线渠道。
6. 收口观察期、AI 交接口径和活文档中的历史内容。

### 非目标

- 不新增产品功能，不改变界面设计与数据语义。
- 不引入运行时依赖、框架、源码目录拆分或新的应用构建链。
- 不为了覆盖率数字制造无意义断言，不重写尚未证明有问题的存储模型。

## 2. 已拍板路线

采用【守约束】：`index.html` 继续内聚应用代码，运行时零依赖、无构建、双击 `file://` 直开。
开发期仍复用现有 Node/Python 检查器，不新增依赖。

备选【破约束】为 ES 模块、构建链、Playwright/Vitest 与自动部署。它能降低模块和协作成本，但会改变双击入口、产物对账与发布方式；用户已明确不选此路。

## 3. 结构设计

### 3.1 缺陷修复

- `sw.js`：导航与静态资源的后台写缓存都纳入 `waitUntil`；缓存失败不阻断已经拿到的网络/缓存响应。
- `Help`：安装成功、拒绝、异常统一清理并刷新按钮。
- `tools/reverse-verify.py`：完整名称匹配；按输出识别锚点腐烂；分别统计干净、无具名红、腐烂、执行异常。
- 老化脚本：保留仍有效的判定点，更新当前代码锚点；无法证明仍有价值的才退役。

### 3.2 单文件模块边界

- 新增 `CoreUI` IIFE，承接共享区控制芯/参数槽/键盘层代码；`Diagnostics` 导出改由装配层注入，不再从共享助手直接调用后方模块。
- `EXPECTED_ORDER` 增加 `CoreUI`，沿用 R1–R4、模块索引、覆盖率分区和规模预算。
- 新增 `LyricHistory` IIFE，承接歌词/音符行级快照、撤销重做与提交；Store 与 AudioEngine 是前向依赖，Arrange 渲染经钩子注入。
- `Arrange` 保留曲式模型、拖拽、打轴与视图，不为追求行数继续拆分。

### 3.3 性能证据

- 冷键写入保留最近样本，输出最近一次、峰值和 p95；不先改 localStorage 数据模型。
- AudioEngine 按当前节奏型快照缓存 `hasStrum` 结果；试听草稿可能原地修改，必须逐轮重算。

### 3.4 闸门与发布

- `publish:check` 改为全量 `--strict-env` 后构建并做本地对账。
- 去除把长期信息读数伪装成到期观察期的配置；真正的模块超期仍按既有规则判红。
- 部署对账分别读取 Cloudflare 与 WorkBuddy；默认只报告线上漂移，显式 `--require-online` 才判红，供发布后验收。
- AGENTS 明确“本人继续工作”与“交接其他会话”两种收尾；预检仍复用现有命令，不造第二套锁。

### 3.5 文档

- 将 DEVELOPMENT 已完成路线与体积预算长期沿革移入 archive，活文档保留当前契约。
- PLAN-v17 与新增历史文档登记到 docs/README；CHANGELOG 继续按大版本分卷。

## 4. 验收

- 新增测试先在旧实现上出现具名失败，再在修复后通过。
- `node tools/check-all.js` 全量通过；新增反向验证覆盖 SW 生命周期、CoreUI/LyricHistory 边界和反向验证入口。
- `npm run build` 后源码与 dist 同版，产物集与安全头一致。
- 双渠道线上读取失败必须明确显示；未经实际发布，不伪报线上已更新。
- 最终 Git 工作区干净，提交后直接推送 `main`，释放写锁。
