01

概述

1.1背景与动机

吉他学习者最常见的挫败不是「不知道弹什么」，而是「弹不准」——抢拍、拖拍、附点弹成八分、切分弹成均匀的十六分。市面上的节拍器（实体或 App）本质都是一个发声闹钟：它用 click 告诉你拍点在哪里，却对拍点之间发生的事保持沉默。而节奏的难点恰恰在拍点之间——时值的比例关系。

BeatSight 的核心主张：把节奏画出来。每个音符被渲染为一个图形，其长度与时值成正比；播放头扫过图形的过程就是演奏过程。四分音符是一格，八分是半格，附点是一格半——差异肉眼可见，而不是停留在乐理书的抽象描述里。

核心概念演示 · 时值可视化（4/4 拍，一小节）
节奏型：四分 → 两个八分 → 附点八分+十六分 → 四分。注意第二条只有第一条一半长，附点组合精确占满一拍 —— 这就是「时值 = 长度」。

1.2目标

  • 业务目标：切入吉他自学工具赛道，以「时值可视化」建立差异化认知，成为吉他练习场景的默认节拍器。
  • 用户目标：让初中级吉他手把「知道节奏型」变成「弹得出节奏型」，缩短从看谱到上手的距离。
  • 北极星指标：周人均有效练习次数（播放 ≥3 分钟计一次）。
  • 关键 KPI：次日留存 ≥ 40%；7 日留存 ≥ 30%；单次练习时长中位数 ≥ 8 分钟；变速训练完成率 ≥ 50%。

1.3范围

  • 本期包含：节拍器核心引擎（音频调度 / BPM / 拍号重音）、时值可视化与播放头、吉他节奏型预设库、播放控制（Must），以及 Tap Tempo、变速训练器、自定义节奏型编辑（Should）。
  • 本期不包含：账号体系与云同步、MIDI/DAW 导出、社区节奏型分享（见 Won't Have，避免范围蔓延）。

用户画像

三个核心角色：一个踩不准拍的新手，一个要提速爬坡的进阶者，一个需要课堂演示工具的老师。

P1

阿澈 · 吉他初学者

自学 3 个月的大学生，跟着视频教程学弹唱
核心目标
把谱面上的节奏型弹准，唱和弹合上拍
主要痛点
看得懂「八分音符」四个字，手却弹不出来；不知道附点到底「多」多少
P2

老周 · 进阶玩家

琴龄 5 年，主攻指弹与 Funk 扫弦
核心目标
攻克切分与十六分音符节奏，稳步提升速度上限
主要痛点
普通节拍器只有均匀 click，练切分时没有参照；手动调 BPM 爬坡麻烦
P3

林老师 · 吉他教师

工作室教师，同时带 6–8 个学生
核心目标
课上演示节奏型、课后布置可执行的练习配置
主要痛点
口头讲解时值抽象低效；学生回家就忘了课上讲的节奏感觉

04

功能需求

4.1功能清单

编号功能名称来源故事描述输入 / 输出
F-001音频调度引擎US-102基于 Web Audio 前瞻调度（lookahead scheduling）的无漂移 click 引擎，后台标签页持续发声输入：BPM、拍号；输出：精准节拍音频流
F-002BPM 设置US-104滑块 + 数字输入 + ±1 步进，范围 30–240，播放中实时生效输入：数值/拖动；输出：当前 BPM
F-003拍号与重音US-303常用拍号（2/4、3/4、4/4、6/8 等），自定义每拍重音强弱，强拍与弱拍不同音色输入：拍号、重音位；输出：分拍音频 + 小节结构
F-004时值可视化引擎US-101, US-301核心差异化：音符渲染为长度与时值成正比的图形（条形/弧线），支持休止符占位、附点、连音线输入：节奏型数据；输出：小节时值图
F-005播放头与当前拍高亮US-102, US-301播放头以音频时钟为基准扫过时值图，当前音符高亮，小节循环无缝衔接输入：音频时钟；输出：同步动画
F-006吉他节奏型预设库US-103内置 ≥8 个常用型：下-下上-上下上、民谣分解 53231323、切分型、Funk 十六分型等，附名称与时值图输入：选择；输出：载入节奏型
F-007播放控制US-104开始/停止（大按钮 + 空格键）、总音量、重拍音量分层控制输入：点击/键盘；输出：播放状态
F-008Tap TempoUS-202连续敲击测速，取平均间隔计算 BPM，异常间隔自动重置采样输入：连续点击；输出：估算 BPM
F-009变速训练器US-201设置起始/目标 BPM、步长、每步小节数，自动爬坡，完成提示输入：训练参数；输出：自动变速播放
F-010自定义节奏型编辑US-203逐拍编辑细分（四分/二八/十六分/附点/休止），时值超限实时校验输入：逐拍编辑；输出：自定义节奏型
F-011静音拍训练US-204周期性静音指定小节（如每 4 小节静音第 4 小节），仅可视化运行，练内心节拍输入：静音规则；输出：间歇音频
F-012本地预设保存US-302配置命名保存至浏览器本地，可加载、重命名、删除输入：配置+名称；输出：预设列表
F-013人声数拍US-304每拍叠加中文数拍人声（「一、二、三、四」），与 click 严格同步输入：开关；输出：数拍音轨
F-014账号与云同步—跨设备同步预设与练习记录本期不做
F-015MIDI / DAW 导出—将节奏型导出为 MIDI 文件本期不做
F-016社区节奏型分享—用户上传/下载节奏型，点赞排行本期不做

4.2非功能需求

维度要求
性能音频调度误差 < 5ms（lookahead 25ms，定时器 50–100Hz）；动画 60fps，播放头与音频偏差 < 16ms；低端机掉帧时优先保音频
兼容性移动优先；iOS Safari 14+ / Android Chrome 90+ / 桌面主流浏览器；处理首次交互解锁 AudioContext
可用性PWA 支持离线使用与「添加到主屏幕」；锁屏/切后台音频不中断（依赖系统策略，尽力而为）
易用性首次进入 30 秒内可开始练习；大字距高对比演奏界面（暗色练习模式）；横屏适配课堂投影
安全 / 隐私无账号、无服务端，全部数据存本地；不上报任何练习数据
可扩展性节奏型与音色为数据驱动（JSON schema），新增节奏型/音色包不改引擎代码

4.3功能依赖关系

  • 地基链：F-001 音频引擎 → F-004 时值可视化 → F-005 播放头（动画必须由音频时钟驱动，反向则必然漂移）。
  • F-002 / F-003 是 F-001 的输入参数，三者同属 MVP 最小闭环；F-006 依赖 F-004 的渲染能力。
  • F-008 输出写入 F-002；F-009 驱动 F-002；F-010 产出物进入 F-004；F-012 序列化以上全部配置。
  • F-011 / F-013 是 F-001 的音轨扩展，相互独立，可并行开发。

07

假设与约束

7.1假设（快速模式下未澄清的决策点）

假设 A
「节奏可视化」= 时值可视化：音符图形长度与时值成正比。若你指的是别的（如力度波形、频谱动画），核心功能 F-004/F-005 需重写。
假设 B
目标用户 = 自学吉他的初中级练习者，兼顾教师演示场景。
假设 C
形态 = 单页 Web App（PWA），移动浏览器优先，无后端、数据全本地。

7.2约束

  • 技术约束：纯前端（Web Audio API + Canvas/SVG）；音频精度受浏览器调度机制约束，必须用音频时钟驱动动画。
  • 业务约束：暂无商业化要求；无内容合规风险（无 UGC）。
  • 时间约束：假设 MVP 开发周期 4–6 周（1 人全栈）。

7.3风险
