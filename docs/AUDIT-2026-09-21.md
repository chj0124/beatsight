## P0 · 真实缺陷

### P0-1 「导入全部数据」静默丢弃全部练习记录

- **位置**：`index.html:2805`（`Store.importAll`）
- **根因**：合并练习记录时校验写的是 `isNum(r.start)`，但时间戳字段从来叫 **`t`**：写入是 `appendSession({t, sec, bpm, name})`（`index.html:5913`），加载校验是 `isNum(r.t)`（`index.html:2408`），导出原样写 `log: sessions`（`index.html:2748`）。
- **后果**：v2.8.8 新上的「导出全部 → 导入全部」链路上，**每条**练习记录都因 `r.start === undefined` 被跳过，`logAdd` 恒为 0、`persistLog()` 不会被调用；导入成功弹窗只显示「练习记录 0 场」。用户换设备恢复数据时练习记录整份消失，且毫无报错——正是全量数据包要防的那类事故。
- **附带**：即便修好字段名，`sessions.push(r)` 是原始对象未经归一化直接入库（加载路径在 2409 有白名单拷贝 + `sec > 0` 校验 + name 截断），导入路径与加载路径两套信任级别；且合并后未按 `t` 排序，破坏 Stats「日志追加写 ⇒ 天然按时间升序」的前提（`index.html:7584`），迷你趋势图乱序。
- **最小修复**：`r.start` → `r.t`；push 换成与 2409 相同的白名单归一化；合并后 `sessions.sort((a,b)=>a.t-b.t)` 再按 `logMax` 截断。
- **反向验证**：构造含 log 的全量包导入，断言 `Store.logSessions.length` 增加。

### P0-2 新增 IIFE 模块静默逃逸全部架构检查（实测复现）

- **位置**：`tools/check-module-order.js:103`
- **根因**：`if (!EXPECTED_ORDER.includes(name)) continue;` 把不在名单里的 IIFE 模块**整个剔除**，而第 0 步顺序检查只比对「已收集的模块」。
- **后果**：新增一个模块（哪怕含初始化期反向引用、真实 TDZ 白屏风险）R1–R4 全绿。实测：注入 `const ZZNewMod = (() => { const leak = Controls.boom; … })()` 后检查通过。唯一兜底是 check-docs 的索引条数≠banner 数（且要求新模块按惯例加 banner），报错指向完全错误的闸门。
- **最小修复**：正则匹配到的全部 `const X = (() => {` 名集合与 EXPECTED_ORDER 做**双向 diff**，多出即报错（与 gen-index「只报错不猜」同约定）。

## P1 · 架构 / 可靠性

### P1-1 wakeLock「授予晚于释放」竞态

- **位置**：`index.html:8814-8826`
- **根因**：`acquire()` 发起 `navigator.wakeLock.request("screen")`（异步），若用户在 Promise 落定前停止播放或关掉开关，`release()` 执行时 `lock` 还是 null（空操作）；随后 Promise resolve、`lock = l`——**屏幕唤醒锁永久持有**，直到页面隐藏被系统回收。
- **后果**：保活开关「关了但没关」，耗电与系统策略代价在用户以为已关闭时继续发生。与 v2.8.8 刚修的 CSP 静默废保活是同一功能区的对称缺陷（那边是起不来不可见，这边是关不掉不可见）。
- **最小修复**：`.then(l => {…})` 里先判「当前是否仍需要」（`if (!(S.keepAwake && S.playing)) { l.release(); return; }`），再赋给 `lock`。

### P1-2 `subCellEls` 声明了、读了、但从未写入（v2.4.4 重构断头路）

- **位置**：声明 `index.html:3668`，唯一读取 `index.html:4643`
- **根因**：注释承诺「建网格时顺手登记一次，帧内只读表」，但 `buildBarRow`（3900–4089）从未写入，`buildViz` 的清空列表（4095–4096）也没有它。表永远是 `[]`。
- **后果**：`paintBeatFlash` 里 `cellNode` 恒为 `undefined` → `onWhite` 恒 `false` → 十六分闪烁在**已弹白块**上永远走 `fc.soft`（淡光）而非设计的 `fc.strong`（强光）。视觉层级静默劣化，也是全文件最大的一处死状态。
- **最小修复**：`buildBarRow` 刻度线循环（`index.html:3989-3994`）补 `subCellEls[b][startT / T16 + u] = c;`，`buildViz` 数组清空处补 `subCellEls = []`。

### P1-3 `loopLyricSection` 裸写 `S.playMode`，绕过 setMode 契约

- **位置**：`index.html:8508`（`S.playMode = "arrange";`）
- **根因**：`setMode` 注释（`index.html:3041`）写明「setMode 是 playMode 的唯一写入口（t66 契约）」，其余 6 处全部走 `setMode`——唯独这里裸赋值。
- **后果**：不进 `modeTrail`（迁移轨迹缺一条）；不触发 `onPlayModeChange` → `Tracks.syncTrackUI()` 不跑，轨说明文字不更新——与 v2.6.3/v2.6.4 修掉的「argJump 残留」同一类半状态。
- **最小修复**：改为 `setMode("playMode", "arrange", "歌词行循环")`，并删掉后面冗余的 `refreshBar()`（onPlayModeChange 已调）。

### P1-4 `Trainer.loopPerSec` 一旦置 true 永不复位

- **位置**：置位 `index.html:8505`；全文件无 `setLoopPerSec(false)` 调用点
- **根因**：「循环本行」把爬坡粒度切成「每整段升一级」，但这是模块级会话状态，`Trainer.reset()`（5572）不复位它，训练开关重开也不复位。
- **后果**：此后**任何**曲式模式下的普通变速训练都悄悄按「整段一级」而非面板的「每 N 小节一级」爬坡，无界面提示。需实测确认影响面（只在曲式模式 + 变速训练同时开时显现）。
- **最小修复**：`Trainer.reset()` 里复位 `loopPerSec = false`。

### P1-5 R1 判据把「顶层块内」误归 R3（实测复现）

- **位置**：`tools/check-module-order.js:176`
- **根因**：`depthOfLine(ln) === mod.bodyDepth` 才判 R1；IIFE 顶层 `if (...) { Modal.x() }` 块内语句深度 +1，被归入 R3（白名单可放行）。但这类语句同样在 **IIFE 求值期执行**，有真实 TDZ 风险——R1「零例外」被一层缩进绕过，且绕过方式是「合法」的（登记白名单即过）。
- **最小修复**：R1 判据改为「不在任何**函数**体内」而非「不在任何块内」——需在括号栈上标记每个 `{` 是否为函数体（保守替代：模块体内、深度 ≤ bodyDepth+1 且不在函数内的引用也按 R1 算）。

### P1-6 「工具故障」退出码约定只修了一半（§E2 残留）

- **位置**：`tools/check-all.js:157` 只认 `TOOL_FAIL_CODE = 4`；但各检查器自身故障路径用 **exit 2**：`check-coverage.js:115`、`check-tsc.js:129`、`check-eslint.js:47/54/105`、`check-dom-ids.js:29`、`check-module-order.js:93`。
- **后果**：这些故障被汇总成「✗ 未通过（退出码 2）」并**中止后续全部步骤**——正是 §E2 要消灭的「故障伪装成失败」，且比 continue 型更糟；与本机沙箱 EBUSY 的已知环境直接相关。
- **最小修复**：统一改为 exit 4，或 check-all 把 2 一并按工具故障记账。

### P1-7 DEVELOPMENT.md「为什么不用 GitHub Actions」整节已过时

- **位置**：`docs/DEVELOPMENT.md:764`（另见 `tools/check-all.js:3`、`tools/install-hooks.sh:3`、`tests/README.md:16` 同款旧口径）
- **根因**：v2.8.8 已落地 `.github/workflows/ci.yml`，`README.md:32` 明说「v2.8.8 起有 CI 了」；两份文档对「有没有 CI」给出相反答案，DEVELOPMENT.md 是 AGENTS.md 指定的第 2 必读文档，误导权重高。check-docs 的七条规则没有一条能抓这种机制级漂移。
- **最小修复**：改写为「本地 check-all 为主、仓库内 CI（v2.8.8 起）为补位」；（可选）给 check-docs 加一条「workflows 存在性 ↔ 文档措辞」规则。

### P1-8 AGENTS.md「16 个 IIFE 模块」事实错误

- **位置**：`AGENTS.md:7`
- **根因**：实际 IIFE 模块为 **14 个**（`tools/check-module-order.js:53` 的 EXPECTED_ORDER 与 index.html 头部模块索引一致：14 模块 + 数据/共享状态/初始化 3 个区块）。"16" 是从 spec.md / tasks.md C5 / checklist.md（均为 2026-09-17 审计、基线 v2.0.2 的历史快照）抄来的旧数。

- **最小修复**：改为「14 个 IIFE 模块（Store…KeepAlive，见 check-module-order.js 的 EXPECTED_ORDER）」，或不写数字、指向索引块。

## P2 · 效率 / 测试体系

### P2-1 全量模式下最贵的测试套件跑两遍

- **位置**：`tools/check-all.js:116,118`
- **问题**：第 12 步 `tests/run.js`（FULL_SCAN=1）与第 14 步 `check-coverage.js --full`（内部再跑一遍 FULL_SCAN=1 套件）各自独立执行完整组合扫描，全链最贵部分直接翻倍。

### P2-2 测试用例清单双份维护、无对账

- **位置**：`tests/hang-guard.js:19` 的 CASES（18 个 id 硬编码）与 hang-case 的派发分支是两份手工清单；`tests/run.js:14` 的 CASE_FILES 与 `cases/` 目录同样无一致性检查（当前各 45 个，恰好一致）。

### P2-3 check-lint 的 eqeqeq/no-var 在未遮蔽字符串上判定（实测复现）

- **位置**：`tools/check-lint.js:97-105`
- **问题**：文件头声称「字符串与注释已剥离，不会误报」，**这是错的**：`stripComments` 刻意保留字符串（`scan-util.js:20`），`maskStrings` 只用于后面的 no-undef。实测字符串字面量 `"a == b"` 被判 eqeqeq 错误。当前全绿纯属 index.html 的字符串恰好不含 `==`/`var x`。
- **最小修复**：这几条规则改在 `maskStrings(flat)` 的输出上跑（等长遮蔽，行号不变），并更正文件头注释。

### P2-4 check-wiring 槽位收列的静默洞

- **位置**：`tools/check-wiring.js:74`
- **问题**：`DECL_RE` 锚定整行 `let onX = null;`，一行多声明（`let onA = null, onB = null;`）**静默不收**，该槽从此不受管辖；且字符串未遮蔽，字面量里出现 `onX = fn` 会被计为装配（假绿）。
- **最小修复**：支持多声明符 + 先过 maskStrings。

### P2-5 check-dom-ids 只认双引号

- **位置**：`tools/check-dom-ids.js:44`
- **问题**：正则只匹配 `$("x")` / `getElementById("x")`，`$('x')` 或模板串引用完全不进审计面（当前代码恰好全双引号，属惯例而非闸门）。
- **最小修复**：正则接受三种引号，或反向断言「禁止 `$(\'`」。

### P2-6 曲式播放中每次块切换重建整个预设列表（需实测）

- **位置**：`index.html:5375` `Presets.scheduleRef(nxt.ref)` → `index.html:7061` `buildPresetList()`
- **问题**：节目单每次换块（示例曲逐小节换型 = 每个小节边界都触发）都全量重建侧栏列表，发生在调度回调里——与注释「小节边界那一轮还要顺手做重活、阻塞超余量就吞拍」（1738-1746）正面相抵。
