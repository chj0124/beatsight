2. **R3（预备拍计入练习量）的处置与方案略有不同**：方案写的是"把 `sessStartT` 基准点移到预备拍结束"，

   因为 `start()` 算 `loopStart` 时已把 N 拍顺延进去）；已在代码注释里写明它不是冗余代码。
3. **新发现的一条已知行为**（方案未预见）：`bars` 模式的**墙钟**停止时刻会早于小节边界最多约 0.85s
   （前瞻窗口 150ms + 一个音符时长）。根因是小节计数在**排程**时累加，而 `stop()` 不取消
   已排入音频时钟的振荡器——所以那 N 小节的音一个不少地响完。**既有变速训练器走的是同一条路径**，
   所以这不是本版引入的问题；已写进 DEVELOPMENT.md §3.2 与 CHANGELOG，并用
   「发声个数 = N × 每小节音数」这个更硬的判据钉住音频层面的"不多不少"。
4. **反向验证扩展为 13 个变异**（方案只写了"把修复退回"）：扫弦 6 个 + 练习量 7 个，全部命中。

### 2.2 P1-A · 扫弦方向标注（v1.9.0）

**目标**：让节奏型能表达 ↓↓↑↑↓↑（下扫/上扫），并让内置的「民谣扫弦」预设真的显示出它名字里的方向。

**数据模型（关键：向后完全兼容）**

```js
// 现在：steps: [{t, rest}]
// 之后：steps: [{t, rest, dir?}]      dir ∈ 'D'（下扫）/ 'U'（上扫），省略 = 不标注
```

- `dir` **可选且与发声完全无关**——它是记谱层字段，`scheduler` 一行都不用改。
  这一点是本项风险可控的根本原因（对比：Swing 也是"演奏参数不入时值"的既有先例，见 DEVELOPMENT.md §3.1）。
- 内置 12 预设中，只给「民谣扫弦 · 下-下上-上下上」补方向：
  `D(48) D(24) U(24) U(36) D(12) U(48)` → 与名称「下-下上-上下上」逐字对应，**顺手修掉一处名不符实**。
- 小节校验（`barSum === meter × TPB`）不变——`dir` 不参与求和。

**渲染**：单元格内渲染方向徽标 `.cell-strum`（SVG 箭头，下扫实心向下 / 上扫描边向上）。
- 复用 `fitCellLabels()` 的宽窄判定（改名 `fitCellAnnotations()`，同时管标签与箭头）——
  十六分格宽仅 6.25%（约 30px），箭头必须能被降级隐藏，否则会糊成一团。
- 遵守既有三条渲染纪律：帧内零 `offset*` 读取、走 `setCell()` 增量重绘路径、不新增每帧 DOM 写。

**编辑器**：编辑区新增「扫弦标注」分段控件（↓ 下扫 / ↑ 上扫 / 清除），作用于当前选中格；
未开启时行为与现在完全一致（零变化）。

**持久化**：不新增 key、不新增开关字段。`dir` 随预设数据走既有冷键 `beatsight.customs`；
导入导出插件原样透传（老 JSON 无 `dir` 仍然合法，导入后就是"无箭头"）。

**校验口径**：`dir` 是**纯装饰字段**，脏值（如 `dir:"x"` / `dir:1`）**静默丢弃为"无箭头"**，
不触发 `beatsight.quarantine` 淘汰——与 v1.2.4「淘汰项不静默丢弃」的纪律不冲突：
那条针对的是**会导致节奏型不可用**的结构性损坏，而箭头丢了节奏型依然完整可用。

**新增测试**：T47 —— ① 箭头按 dir 渲染且下/上可区分；② 脏 dir 丢弃且不影响小节校验；
③ 导出→导入往返保留 dir；④ 无 dir 的旧数据零箭头；⑤ 窄格自动隐藏箭头；⑥ 内置民谣预设方向与其名称逐字一致。

**成本**：约 1 个开发批次（与 v1.8.0 同量级）。**风险**：见 §5。

### 2.3 P1-B · 练习量控制（v1.9.0）

**目标**：说得出"练多少"——练满 N 小节 / N 分钟后自动停，并让这次练习自动进练习记录。

**数据模型**

```js
S.limit = { mode: 'off' | 'bars' | 'min', n: number }   // 进热键 beatsight.state
```

**两种模式的计时口径（需你确认，见 §6 待确认问题）**

| 模式 | 计数方式 | 理由 |
|---|---|---|
| `bars` | 在 `scheduler` 的**小节边界分支**累加 `limitBars`，达到 N 即 `Controls.stop()` | 与可视化、练习记录同为小节粒度；预算时间可精确到拍 |
| `min` | `ctx.currentTime - sessStartT >= n × 60` | 复用既有练习记录的会话起点，口径统一；`ctx.currentTime` 单调且不受后台节流/重新锚定影响 |

- **不计入预备拍**：`sessStartT` 应在预备拍结束后（`loopStart` 起）才作为基准，
  否则"练 5 分钟"会被预备拍偷走几秒。需在实现时把基准点从 `start()` 移到"预备拍结束"。
- **与变速训练器共存规则**：两者都开时，训练器照常爬坡，**谁先到谁停**。
  完成文案要能区分（"已达目标速度" vs "已练满练习量"）。

**UI**：训练模式区加一行「练习量」分段档 —— `不限 / 8 小节 / 16 小节 / 32 小节 / 5 分钟 / 10 分钟` + 自定义输入。
进度复用训练器进度条位置显示「练习量 12 / 32 小节」。

**新增测试**：T48 —— ① bars 模式恰好在第 N 小节边界停（不提前、不多走）；② 与变速训练器组合，先到者停且文案正确；
③ min 模式按音频时钟；④ 预备拍不计入；⑤ 脏值回退 `off`；⑥ `off` 模式行为与现在逐帧零差异。

**成本**：约 1 个开发批次。**风险**：动的是 `scheduler` 小节边界分支——**全项目最敏感的路径**，见 §5。

### 2.4 P2 · 听辨训练（v1.10.0）

**目标**：随机播放一个节奏型（只看得到"在播"，看不到长什么样），用户从候选里选出正确答案，计分。
把「解决听不出附点/切分」从口号补成闭环。

**新增模块 `Ear`**（排在 `Stats` 之后、`KeepAlive` 之前，并在 `check-module-order.js` 的依赖顺序表登记）。

**复用而非重造音频**：现有试听机制是 `S.preview=true` 时 `curPattern()` 返回 `draft`。
把它**泛化为一处**：`curPattern()` 在 `S.previewRef` 存在时返回该对象。
Editor 设 `previewRef = draft`，Ear 设 `previewRef = 候选题` —— **仍然只有一个音频引擎**，
绝不另起一套调度（那会立刻产生双时钟、双热键、双缓存）。

**题目质量的关键设计：易混组而非随机抽题**

随机从 12 预设抽题会出"送分题"（八分摇滚 vs 华尔兹根本不会听错）或"无解题"。
改为手写**易混组**，候选只从同组里出：

| 易混组 | 候选 | 练的是什么 |
|---|---|---|
| 附点系 | 附点布鲁斯 / 八分摇滚 / 三连音基础 | 附点 vs 均分八分 vs 三连音——最常见的"听不出来" |
| 切分系 | 切分节奏型 / 八分摇滚 / Funk 十六分 | 切分重音位移 |
| 奇数拍系 | Take Five 5/4 / Money 型 7/4 / 3+3+2 | 奇数拍分组 |

**流程**：进入 over/`Controls.stop()` → 「播放题目」播 2 小节 → 从 3 个候选里选 → 即时对错反馈
（`srAnnounce` 播报，无障碍与既有分级播报纪律一致）→ 统计正确率 / 连对数 / 历史最好 →
存冷键 `beatsight.ear`（与 `beatsight.log` 同类，**不进热键**）。

**新增测试**：T49 —— ① 出题只从同组取且答案唯一；② 判分与连对计数；③ 进入时强制停播、退出恢复；

**成本**：约 1.5 个开发批次。**风险**：见 §5。

### 2.5 P3 · 曲式编排（v2.0.0，待立项）

**目标**：把多个节奏型串成曲式——`[前奏: 民谣扫弦 ×4] → [主歌: 切分 ×8] → [副歌: 八分摇滚 ×8]`。

**为什么单独立项**：当前音频核心是**严格 4 小节循环**（`schedBar ∈ 0..3` + 单锚点 `loopStart`）。
要支持任意曲式，必须把"循环"抽象成"**节目单 + 游标**"，这会同时动
`scheduler`（小节推进）、`activePattern()` 快照语义、`buildViz`（同屏小节数不再是恒定 4）、
`paintFrame`（行数/进度）、以及 T12/T15/T20/T21 一大批相位不变量的前提。

**建议**：先只出设计探针（不动代码），回答三个问题：① 曲式怎么表达与存储；
② 跨段落切换沿用 P1 已用的"相位就地接续"还是退回小节边界挂起；③ 可视化同屏小节数怎么变（固定 4 行滚动 vs 按段落自适应）。
评估通过再动工。

### 类型闸门落地纪要（v1.9.1）

方案里只写了「JSDoc + `tsc --checkJs --noEmit`，照 ESLint 模式接入」，实际落地比这句话具体得多，
几条经验值得记下来：

1. **严格模式没法一步到位**：`noImplicitAny` 打开立刻 727 条报错（v1.9.1 落笔时按当时口径记为 759；
   2026-09-16 在 TS 7.0.2 + 现树下重测为 **727**，"隐式 any"占 55%）。当时最终口径改为
   「`checkJs` 开着、严格开关关着」——听起来很弱，但**并不空转**：落地时实测抓到 6 类真问题
   （46 处 `EventTarget` 取值、22 处 `$` 元素类型、`textContent` 被赋数字、`onLimitPulse` 名字遮蔽等）。
   开启路径写成"逐块补标注、逐块开开关"，别一次性开。**2026-09-16 已按这条路径推进第一步**：
   共 **8 项**严格检查实测 0 报错（strict 家族 6 项：`strictFunctionTypes` / `strictBindCallApply` /
   `noImplicitThis` / `alwaysStrict` / `useUnknownInCatchVariables` / `strictBuiltinIteratorReturn`；
   另加非家族的 `noImplicitReturns` / `noFallthroughCasesInSwitch`），已直接打开。
   **2026-09-17 已推进第二步**：`noImplicitAny` 分两批补完全量前置 `@param` 与内联 `@type`
   （727 → 282 → 0）后打开，strict 家族至此已开 **7 项**。
   **同日推进第三步（收官）**：`strictNullChecks` 那 **96** 条（TS18047 74 / TS2345 10 / TS2322 4 /
   TS18048 4 / TS2769 3 / TS2531 1）按模块分七块逐块消化——Trainer 6（`S.plan`）→ 小尾 9
   （Arrange 4 + Ear 3 + Store 1 + Modal 1）→ Controls 11 → Audio 20（`ctx`）→ Viz 25（缓存 DOM 引用）
   → Editor 25（`draft`），统一用「取本地别名 + 判空守卫」（模块级可空 `let` 在函数顶部取别名并早返回、
   定时器句柄先判 `!== null`、`.closest()` 补 `!!`），**96 → 0** 后打开。strict 家族至此已开 **8 项**
   （`strictPropertyInitialization` 随 `strictNullChecks` 生效，本文件无 class 故无影响），
   **与两项额外严格检查全部打开且全绿，类型闸门扩面就此收官**。
2. **`S` 的类型标注是闸门真正长牙的地方**：不标注时 `noImplicitAny:false` 让 `S` 的属性全是隐式 any，
   `S.limit.noSuchField` 这种笔误能大摇大摆通过（实测过）；补 12 行 `@type` 之后，
   `S.trainr.on` 会报 `Did you mean 'trainer'?`。**给中心数据结构标类型，比给全文件补类型划算得多。**
3. **抽取文件末尾要补一行 `export {};`**：按全局脚本检查时，tsc 会认为模块名 `Audio` 与 lib.dom 的
   `declare var Audio` 冲突，并把 4 处 `Audio.scheduler` 解析成 HTMLAudioElement 的属性——5 条假报错。
   按模块检查更贴近真实作用域，且其余检查一条不松。追加在末尾，行号映射不受影响。
4. **装一次 `npm install` 就有产出**：`onLimitPulse` 名字遮蔽正是 ESLint `no-shadow` 抓到的，
   不是我读代码发现的。而在此之前，本仓库从 v1.6.5 起就没装过 `node_modules`——
   所谓"接入了 ESLint"其实是**从未跑起来过的**，汇总却一直显示 ✓。
5. **顺带修掉那个假绿**：`check-all.js` 只认退出码，而可选步骤按设计就是缺依赖时 exit 0，
   于是"没查"和"查了通过"长得一样。现在由 check-all 自己检查依赖、缺了标 ⊘ 且不调用，
   汇总打印「实跑 N/M 项」。**这比多修一个 bug 重要——它决定其余所有 ✓ 可不可信。**
